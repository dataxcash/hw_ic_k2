# K2 pm_gate — EDA 会话执行门禁（承接纪律，v1）

> **状态**：2026-09-03 定稿（m13 Q2 求解 session 教训固化）。所有承接 EDA 确定性求解 /
> 几何判定任务的会话（含 LLM 主会话）**动手前必读**，并遵守 G0-G5。
> **目的**：杜绝"模型层与学习资产空转、会话自行发明求解器/试错"的乱干模式。
> **核心**：先检索 → 判覆盖 → 覆盖则消费、**不覆盖则 STOP 上报**；失败熔断，禁止空转。

## 触发与适用

- 任务含"几何求解 / 布局可行性 / 扇出判定 / 形态判定 / 可行性结论"等确定性判定时适用。
- 与既有铁律继承关系：零单板特判 / 假成功零容忍 / 问题回模型 / 学案例≠修引擎 /
  冲突即停机 / 结论未出不改摆件不改引擎——本门禁是这些铁律在**承接期**的执行化。

## G0 — 权威承接完整阅读（动手前置）

- 读全 handoff 指定的权威清单（含该任务涉及的 `_shared/docs/*`、案例/约束设计文件），
  不只读 handoff 本身。handoff 的"权威承接（按序读）"段是命令不是建议。
- Session 开头输出一行承接清单：`已读：[文件…]`。清单未满 → 不得进入实现。

## G1 — 资产检索先行（每个求解问题必做）

- 求解问题出现时，先真实检索下列资产并引用结果（禁止凭印象声称"查过"）：
  1. 案例库模板：`kb.sqlite3` / knowledge_base（已学形态、known_gaps、先例）
  2. `escape_learner` 形态化输出（真板案例：PEX8748 / AIC PEX88096 / OpenCAPI…）
  3. 模型层接口：`route_input` / `hs_route_model` / `ls_route_model` / `channel_alloc` /
     `escape_landing` 是否已有该形态的输入通道或半成品
  4. `_shared/docs/*` 约束/设计文件（含本任务权威件）

## G2 — 覆盖三态判定并显式声明

| 检索结果 | 动作 |
|---|---|
| 已覆盖（有先例/接口可消费/文档已定义） | **消费**：作为输入、基线或校验源，引用其结论 |
| 部分覆盖 | 列出差距（缺什么形态/数据），补足后继续 |
| **未覆盖** | **STOP**：输出"模型缺口报告"（缺哪个形态、模型层需提供什么），交 PM/用户裁决。**禁止自行发明等价结论或假装模型层无责** |

## G3 — 临时求解器职责边界

- 允许编写"证书求解器"（构造性证明/反例），但产物必须标注：**非引擎、非模型结论，
  仅几何判定证据**。
- "有解 / 无解"的最终判定不得以临时脚本替代模型层；必须回流为模型缺口或案例证据，
  供层3/层4 消费。

## G4 — 失败熔断（禁止空转）

- 同一几何卡点**连续 2 个独立尝试轮次无新证据**（换了参数/布局仍在同一卡点打转）
  → **立即停止试错**，转写"问题回模型"报告：卡点（哪一对/差多少）、缺的形态、
  需要模型层/摆件/案例库提供什么。禁止第 3 轮盲目换参。

## G5 — 收尾自检（写入 handoff，下 session 先读）

- 每个 session 收尾必须回答并落盘：
  1. 本轮消费了哪些模型/学习资产？（模板 / learner / route_model / docs，逐项引用）
  2. 哪些未消费？为什么？（若为"未覆盖"→ 应已有缺口报告，二者必居其一）
  3. 本轮的停止/熔断事件记录（触发了几次 G2/G4）

## 停止信号（"模型与学习不起作用"的操作化判定）

完成 G1 检索后，满足任一即判定"资产对该问题不起作用"，**必须 STOP 上报，不得进入自创求解**：

1. 案例库/文档无该形态先例，且无类似形态可类比；
2. 模型层接口无对应输入通道，且文档未定义该几何域；
3. 检索过程中发现权威文档/既有结论与本会话假设冲突（冲突即停机，先对账）。

反之，只要检索到可引用形态、可消费接口或可作基线的既有结论 → 先消费，再动手。
