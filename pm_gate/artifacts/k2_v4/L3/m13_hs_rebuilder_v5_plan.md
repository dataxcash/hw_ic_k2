## 0.1 v4.4 暴露的核心缺陷（本次计划必须解决）

**缺陷 A — flip=True 逃逸构造 P/N 交叉（方案级）**
flip=True 下 P 接下轨（track_y-0.19）但 pad 位于上侧（y>轨）→ P 竖线从 pad 下落到
下轨**物理上穿越 N 走廊轨**。实证（UP3）：
- input：P 竖线 (88.17,45.05→45.7) 穿越 N 水平段 (65.5→88.17, 45.43)，中心距 0.0000
- out_U7：P jog 水平段与 N 竖线在汇入点交叉
- out_J2：P/N 斜线交叉
根因：差分对内豁免 → P/N 互不检测 → seg_ok 放行 → 断言拦截（事后）。
**修复方向**：flip 适用性几何约束 + P/N 分侧接入（见 §2-B）。

**缺陷 B — 无区域容量分析（"空间不够"无证据）**
现状仅单对探针（probe_escape_capacity 逐候选近障碍距离），无区域级容量地图。
v4.4 曾声称"引脚区容量不足"——经几何粗算（0.4 脚距 × 16 引脚 = 3.2mm < 引脚区 4mm，
相邻线边缘距 0.195 ≥ 0.175）**证据不成立**。120×38mm 8 层（4 信号层 × 16 对/层容量
vs 18 对需求）空间富裕。
**修复方向**：区域容量探针 probe_region_capacity（§2-A）——容量判断以模型输出为准。

**缺陷 C — 固定求解顺序（先到先得占歪轨道）**
solve_all_v4 固定序 UP0→UP7 → 先解对占位（段偏斜侵入相邻轨）→ 后解对无路。
探针 nearF=-0.075（压线）是**顺序产物**非物理容量。
**修复方向**：全局通道分配（§2-C）——轨道归属由分配决定，非顺序。

**缺陷 D — 数据对换层能力未放开**
esc_layer 已参数化（REFCLK 用 In6），但数据对仍仅 F.Cu 直连/In2 换层两形态。
PM 裁决"层无约束" → 数据对可全程 In2/In4 绕行（受控过孔 ≤2、P/N 同层保持）。
**修复方向**：换层形态扩展（§2-D）。

## 1. 容量验证计划（"空间够不够"的证据标准）

### 1.1 容量地图（Capacity Map）——每瓶颈区最大可容纳对数

| 区域 | 对象 | 需求 | 判定输出 |
|---|---|---|---|
| U7 引脚区 | UP0-7 out_U7 逃逸 | 8 对 | 最大可容纳对数 + 冲突集合 |
| U3 引脚区 | DN0-7 out_U3 逃逸 | 8 对 | 同上 |
| J2 连接器 | 16 对逃逸（UP 侧） | 16 对 | 同上 |
| J3/J4 连接器 | 16 对逃逸（DN 侧） | 16 对 | 同上 |
| 走廊 | J2_TO_U / U_TO_MCIO | 8 对/带 | SPEC 设计已 8 对（复核） |

**判定语义**（模型输出，零人工）：
- `CAPACITY_OK`：N 对可同时出列（组合枚举净空，非单对）
- `INSUFFICIENT`：输出最小冲突对集合（哪几对同时布必撞、撞哪个障碍、距离多少）

**证据标准**（"空间不够"的唯一合法出处）：
1. 区域容量地图（组合计算）
2. 集合可行性证明（N 对同时布线冲突不可消除——换轨/换层/换顺序均已尝试）
3. 冲突的物理不可动性（障碍归属：pad/GND via/固定器件——器件可动裁决下此条放宽）

### 1.2 验证流程（七步法：先算容量再布线）

1. **容量地图先行**：4 瓶颈区 + 2 走廊全量出图 → 落盘 `artifacts/k2_v4/L3/model_solves/hs_rebuild_v5/capacity_map.json`
2. **容量裁决**：CAPACITY_OK 区 → 进入求解；INSUFFICIENT 区 → 集合证明落盘（等 PM，不硬挤）
3. **单条验证**：每区先手工验证 1 条完整链路（连接器→走廊→芯片，净空+层协议+等长）
4. **全量求解**：18 对（链级事务 + shared 累积 + 断言）
5. **落板验收**：副本 DRC → 高速 0 违规（或带证明残余，PDN 冲突登记 S3）

## 2. 模型加强实施计划

### 2-A. 区域容量探针 `probe_region_capacity`（新能力）

- 位置：`hs_route_model.py`（HSRouteModel 方法，与 probe_escape_capacity 同族）
- 输入：区域类型（pin_region/connector/corridor）+ 需求对数 + 候选形态集
- 算法：区域可用宽度扫描（pad 出列可达轨数）→ N 对组合出列可行性（确定性枚举，
  禁全图搜索——铁律）→ 冲突集合提取
- 输出：`{region, demand, capacity, status: CAPACITY_OK|INSUFFICIENT,
  conflict_sets: [{pairs, obstacle, dist}], geometry_evidence: {...}}`
- 复用：`_probe_fields`（段级清出同口径）、`_escape_pair` 形态枚举、`_pn_spacing_check`
- 验证：四区 + 两走廊容量地图落盘；与几何粗算（§0.1 缺陷 B 数据）交叉核对

### 2-B. flip 逃逸形态重设计（缺陷 A 修复）

根因：flip=True 的 P 竖线穿越 N 走廊轨（pad 上侧 + P 接下轨）。

**方案（候选，容量地图验证后定稿）**：
1. **flip 适用性几何约束**：仅当 pad 对中心位于 P 轨与 N 轨之间（或同侧无穿越）
   时允许 flip——pad 侧判定前置，不满足则 flip 不可用（转其他形态）
2. **P/N 分侧接入**：flip 时 P 竖线与 N 竖线不同 x 汇入（P 先落到 P 轨，N 轨段
   错位让出穿越区）——走廊段 P/N 轨 x 范围错开（构造保证 P 竖线不穿 N 轨）
3. **换层替代**：flip 场景优先走 esc_layer 换层（In2/In4，缺陷 D 放开后可用），
   F.Cu 直连仅保留无穿越场景

- 验收：原子性断言（P/N 边缘距 ≥0.175）全链通过；flip 段 P/N 中心距 ≥0.175
  （不再是 0.0000）
- 约束：确定性（固定候选序）、零随机、零 revA 特判

### 2-C. 全局通道分配（缺陷 C 修复）

- 现状：固定序先到先得（轨道占歪）
- 方案：求解前用容量地图（2-A）对每个引脚区计算"需求对的可行轨道分配组合"
  → 输出分配表（net → track_y → 形态）→ 写入求解输入（channel_alloc 修订或
  RouteInput 扩展）
- 判定：每对轨道归属由分配决定（非顺序）；分配组合枚举确定性（禁回溯搜索）
- 验证：分配后全量求解——不再出现"先解占位后解无路"（同区对全部 SOLVED 或
  全部带集合证明）

### 2-D. 数据对换层形态扩展（缺陷 D 修复）

- esc_layer 参数化已就绪（REFCLK→In6）→ 数据对走廊段/逃逸段支持 In2/In4
- 约束：受控过孔 ≤2/侧、P/N 同层保持（原子性断言覆盖）、等长（蛇形单侧向）
- 场景：引脚区 F.Cu 直连拥挤（容量地图判定）→ 换层绕行；REFCLK 已示范
- 验证：UP/DN 各段换层路径净空 + 断言通过

### 2-E. 验证体系强化（防假成功再犯）

| 断言 | 现状 | 增强 |
|---|---|---|
| P/N 间距（原子性） | ✅ v4.4 已加 | 保留（阈值 0.155 容差） |
| via 冲突（段 vs via） | 段累积已含 via | 落板前断言：新段与 via 净距 ≥0.175 |
| 集合一致性 | 链级事务 | 容量地图组合断言（同区 N 对互不压线） |
| 落板协议 | layers 计数 | 保持不变（hs_apply skipped=0） |

## 4. 铁律约束（实施期间禁止违反）

1. 七步法：先容量后布线 / 先单条后全量 / 失败带证据（模型输出）
2. 反暴力迭代：同输入重跑 ≥2 次即停转 Plan；单对 >5s 停转 Plan
3. DRC 只核对：不拿 DRC 报告修产物；DRC finding → 追溯模型/输入
4. 方案即模型输出：任何"空间不够/可解"结论必须来自模型 API（容量地图/断言）
5. 零 revA 特判：全部能力入参纯粹、通用（数据驱动 SPEC/规则）
6. 分析走模型 API：禁止一次性脚本手算（容量地图是模型能力，不是临时脚本）
7. 冲突即停机：模型输出与物理事实冲突 → 中断 → 冲突报告
