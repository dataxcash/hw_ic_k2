# EDA 自动化进化规划 — 拓扑可布性门禁（Topology Routability Gate）

> 状态：规划（待 PM 确认后执行）
> 触发：M13 v5 高速域改造卡壳复盘（2026-08-26）
> 定位：**原理图 → PCB 之间的缺失环节**——本次 16 对高速线 15 对布不通的根因不在布线层，
> 在"网表拓扑 × 器件布局"的交叉；现有没有任何模型在此环节做验证。
> 铁律：先画图后算数 / 方案即模型输出 / 分析走模型 API（禁临时脚本）/ DRC 只核对不驱动 /
> 修订走输入 / 假成功零容忍 / 可重复可追溯（红队可审计）

---

## 1. 问题复盘（为什么卡了五轮）

### 1.1 现象
- 18 对高速差分线（PCIe），M13 v1→v5 五轮改造，真实布通仅 1 对（REFCLK0）
- 每一轮都在"布线算法"层面死磕（逃逸形态/flip 重设计/换层/轨道对齐/断言），
  局部不断改善，但链级始终被"结构性交叉"卡死

### 1.2 根因（TOP VIEW 层，非布线层）
- **网表按"信号方向"分工**：U7 管全部上行（UP0-7，从 MCIO→J2），U3 管全部下行（DN0-7，从 J2→MCIO）
- **连接器按"物理位置"分布**：J3 在上排（y≈44.5）、J4 在下排（y≈62.7），各 4 lane（lane 双向：TX+RX 捆绑）
- 结果：J3 同时接 UP0-3（去上排 U7）和 DN0-3（去下排 U3）→ **8 对必交叉**
  （UP4-7 从下排 J4 斜穿到上排 U7；DN0-3 从上排 J3 斜穿到下排 U3）
- 交叉路径撞 U3 区域 + 32 颗 AC 耦合电容墙 → **布线层无论如何优化均无解**

### 1.3 教训
1. **七步法"先画图后算数"未前置**：应第一件事画 TOP VIEW 检查"谁接谁"，而非直接调算法参数
2. **验证全在布线层**：容量地图/断言/DRC 都只验证"给定网表+布局下布不布得通"，
   不验证"这个网表+布局的组合本身是否合理"
3. **原理图阶段无预检**：网表生成后直接进 PCB，中间没有"拓扑可布性"检查环节

## 2. 架构缺口（现有模型盲区）

| 环节 | 现有模型 | 管什么 | 缺口 |
|---|---|---|---|
| 原理图生成 | sch_gate（结构三基础/ERC/出图门禁） | 图纸正确性 | **无"网表 vs 目标布局"可布性检查** |
| 原理图 → PCB | （无桥梁） | — | **缺拓扑可布性门禁**（本次根因） |
| PCB 布局 | 人工/约束（宪法） | 器件位置 | 无"排布合理性"模型（哪个器件该放哪、是否交叉） |
| PCB 布线 | hs_route_model（容量地图/求解/断言/DRC） | 布不布得通 | 已较完整（M13 v1-v5 沉淀） |

**一句话**：原理图模型管"图对不对"，PCB 模型管"线通不通"，中间没人管"这个接法+这个摆法，物理上有没有交叉"。

## 3. 改造方案（分三层，逐层固化）

### 3.1 L1：拓扑可布性探针 `probe_link_topology`（新模型能力）

**位置**：`_shared/eda_core/hs_route_model.py`（HSRouteModel 方法，与 probe_region_capacity 同族）
或独立 `topology_gate.py`（若 K1 也需要则独立模块，零 revA 特判）

**输入**（全部来自正式输入文件，数据驱动）：
- 网表（谁接谁）：原理图生成器的 nets 输出（正式来源）
- 器件位置 + 引脚分布：SPEC components / BoardParser pads（正式来源）
- 链路定义：chain_segments 配置（正式来源）

**算法**（确定性枚举，禁全图搜索）：
- 逐链路提取两端 pad 对中心（连接器端 + 芯片端）
- 判定：两端 y 偏差 < 阈值（同排，默认 0.4mm）→ 同排直连候选；偏差大 → 长跨距/交叉候选
- 对交叉候选：输出障碍证据（跨过哪些器件区域/电容墙，nearest 证据）
- 组合判定：同区 N 链路同时同排（复用 _corridor_clear_span 排除器件影响区）

**输出**（落盘 JSON，红队可审计）：
```json
{
  "probe": "link_topology", "version": "1.0",
  "input_fp": "...",
  "links": {
    "UP0": {"conn_end": [x,y], "chip_end": [x,y], "y_delta": 0.1,
            "verdict": "ALIGNED" | "CROSSING" | "LONG_SPAN",
            "obstacle": {...}},
    ...
  },
  "verdict": "TOPOLOGY_OK" | "CROSSING_FOUND",
  "crossing_links": [...]
}
```

**验收**：确定性（同输入同输出）/ 落盘 / 红队可审计 / 单测覆盖

### 3.2 L2：布局可行性分析（从"判定交叉"到"如何不交叉"）

- 基于器件包围盒 + 引脚分布，输出"排布修订建议"（数据驱动）：
  哪个器件该与哪个同排、哪些信号应同属一个芯片（按 lane 分组）
- 支撑 PM"器件可动"裁决的可执行化（修订建议 → 布局输入修订）
- 本次案例：U7 管 lane0-3（J3 全接 U7 上排）、U3 管 lane4-7（J4 全接 U3 下排）、
  J2 引脚按上下排重映射——由模型输出建议，非人工拍脑袋

### 3.3 L3：流程固化（门禁接入）

把拓扑可布性检查接入**原理图 → PCB 的必经环节**（与 G2.6 escape_closure 同格）：

```
原理图网表生成 → [G-Topo 拓扑可布性门禁] → PCB 布局 → 布线 → DRC
                      │ FAIL：返回原理图修订（改接线分工/器件排布）
                      │ PASS：进入布局布线
```

- 新 gate：`topo_routability_check`（挂 L1/L2 阶段，仿 G2.6）
- 硬指标：全部高速链路 ALIGNED（或带方案级裁决的豁免记录）才放行
- 该门禁对 K1/K2 通用（零 revA 特判，入参纯）

## 4. 里程碑与验收（每步硬闸门，不过即停）

| 里程碑 | 内容 | 验收（模型输出，非口头） |
|---|---|---|
| **M-A** | 建 `probe_link_topology`（探针 + 单测 + 落盘） | 确定性、可审计；单测绿 |
| **M-B** | 对**当前网表**出拓扑报告 | 报告抓住 UP4-7/DN0-3 共 8 对 CROSSING（验证探针真能发现问题） |
| **M-C** | 对**新拓扑**（U7=lane0-3、U3=lane4-7、J2 重排）出预检报告 | 16 链路全 ALIGNED（改网表前的预验证，零改动成本） |
| **M-D** | 改网表（ECO：接线分工重排） | 原理图模型验证：结构三基础 + ERC 0 + 出图门禁全绿 |
| **M-E** | 重生成 PCB → 容量地图 → 全量求解 | 16 对全 SOLVED + P/N 断言全过 + 等长 <0.15 + 单对 <5s |
| **M-F** | 落板 DRC | 高速 0 违规 + 0 未连接（或带证明残余登记） |
| **M-G** | 门禁固化（L3 接入流程） | topo_routability_check 进 pipeline，K1/K2 通用 |

**总验收**：拓扑可布性门禁成为原理图→PCB 的正式环节；本次 16 对高速线全部真实布通
（无假成功）+ 全程模型输出可追溯。

## 5. 本次问题沉淀的体系价值（用户定义："问题促使 EDA 自动化进化"）

| 沉淀 | 内容 |
|---|---|
| **新门禁** | 原理图→PCB 之间新增拓扑可布性检查（此前不存在）——本次根因的唯一防线 |
| **布线层能力** | M13 v1-v5 沉淀：容量地图/flip 双极性/换层形态/P-N 断言/链级原子事务——K1/K2 通用，新拓扑下直接复用 |

| **方法论** | 布线层无法解决的问题，必须上探到拓扑/布局层（问题分层定位，禁止在错误层死磕） |

## 6. 风险与边界

- **网表重构风险**（M-D）：U7/U3 角色分工 + J2 引脚重映射是原理图级变更，
  可能影响 ReDriver 配置（DS160PR810 的 EQ/极性设置随通道变化）——由原理图模型
  （ERC/结构门禁）+ ReDriver 配置校验覆盖
- **J2 引脚重排的物理约束**：J2 连接器引脚位置固定，重映射必须满足"U7 信号全在上半、
  U3 信号全在下半"且每根线从芯片到引脚同排——由 M-C 预检先行验证
- **K1 兼容**：L3 门禁必须零 revA 特判（K1 走同样流程，输入不同）
