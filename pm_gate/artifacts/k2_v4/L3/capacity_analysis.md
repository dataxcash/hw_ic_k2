## 2. 各端逃逸容量（探针证据，逐候选）

### 2.0 机制性物理约束（DRC 实证 + 探针公式）

`diff_pair_dimensions=[]` → P/N 是独立网，0.175 净距强制。探针显式输出物理事实：
**P/N via 中心距 == P/N pad 中心距**（同方向同距离平移不变）；via 边距 = 中心距 − 0.35。
→ via 边距 ≥0.175 需 **中心距 ≥0.525**。引脚区 0.4 对距 → via 边距 0.05 → **双 via 物理不可能**。

### 2.1 U3/U7 引脚区（input left、out_U3 right、UP 同构）—— 结论：**F.Cu 直连，禁 via**

| 探针 | 值 | 判定 |
|---|---|---|
| P/N pad 中心距 | 0.4mm | via_edge 0.05 < 0.175 → **双 via 不可行** |
| 候选 via 落点 | 全部 fcu_ok/esc_ok=False，nearest=相邻引脚 pad（VREG1_U3 / GND / 相邻对 pad，d≤0.17） | via 落点被引脚列阻挡 |
| F.Cu L 形直连（右出列→上行） | P_ok=True N_ok=True，nearest=VREG1_U3 d=0.60 | **✅ 可行（无 via）** |
| F.Cu 垂直上行 | 穿 N pad（P pad 顶到 N pad 底仅 0.15mm） | ✗ 不可行 |
| F.Cu DIAG 斜线 | N 侧穿障碍 | ✗ 不可行 |

**容量计算**：U3 引脚区 8 对差分（0.4 脚距 = 16 引脚 6.4mm 宽）右出列后上行，P/N 线 0.38 对距 + 0.175 净距 → 8×0.38 + 7×0.175 = 4.27mm < 6.4mm 引脚宽度，**容量足够**。逃逸通道 = x>99.05 芯片右侧区（探针验证无密集障碍）。

### 2.2 J2 连接器区（input right、UP out_J2 同构）—— 结论：**via 换层可行但落点须列间空隙**

| 探针 | 值 | 判定 |
|---|---|---|
| P/N pad 中心距 | 2.35mm → via_edge 2.0 | via 间距 ✅ |
| 候选 via（沿 pad→走廊方向外移） | k=1..4 全 fcu_ok/esc_ok=False，nearest=GND pad / PCIE_DN1_N / I2C1_SCL（d≤0.17） | 沿 u 外移撞相邻 pad |
| 可用空间 | 列间 1.05mm（133.3..134.35）+ 外侧 7.35mm（x>135.65 到板边 143） | 物理空间存在 |

**容量计算**：J2 区 36 个 PCIE pad（18 对）+ GND 伴行 pad 交错。via 落点须选 **pad 列间/外侧空隙**（探针候选方向不对，非容量不足）。36 条逃逸线 × (0.38 对距 + 0.175 净距) ≈ 20mm 需求 vs 列间+外侧总宽 ≈ 8.4mm/侧——**单侧不够，必须双侧分摊 + In2 层复用**。判定：J2 逃逸是"落点策略缺口"（缺陷 1 修复），非物理不可行。

### 2.3 电容墙区（out_U3 left、out_MCIO right）—— 结论：**x 向穿墙不可能，须 y 向/墙外**

| 探针 | 值 | 判定 |
|---|---|---|
| P/N pad 中心距 | 1.3mm → via_edge 0.95 | via 间距 ✅ |
| pad x 间隙 | **0.2 / 0.3mm**（单线需 0.205+0.35=0.555） | **穿墙布线不可能** |
| 候选 via（沿走廊方向） | fcu_ok=False，nearest=相邻电容 pad（同墙） | 落点被墙阻挡 |
| 非 PCIE 障碍 | 仅 3 个 GND via（x=75.77/81.48/81.77） | 墙区 F.Cu 相对空旷 |

**容量计算**：电容 pad 高 0.5（y 向），行间净空 5.95mm（DN0 行 y=66 → DN1-3 行 y=60.05）。DN0 电容（x∈[75.28,77.67]）上方 5.95mm 内无其他电容 → **y 向出线 + via 换层绕行可行**（DN0 行下方至板边 5mm 也可用）。判定：电容墙逃逸是"方向选择缺口"（缺陷 1 修复：pad 侧自适应 + 墙外锚定），非物理不可行。

### 2.4 MCIO 连接器区（out_MCIO left）—— 结论：**CAPACITY_OK（探针全绿）**

| 探针 | 值 | 判定 |
|---|---|---|
| P/N pad 中心距 | 0.6mm → via_edge 0.25 ≥ 0.175 | ✅ |
| 候选 k=1..4 | fcu_ok=True esc_ok=True，nearest=GND pad d=0.35 | ✅ 全部可行 |

**容量计算**：MCIO 端 4 对（DN0-3 到 J3）/4 对（DN4-7 到 J4）via 逃逸物理可行。现有 _sym_via 几何可直接复用。

## 3. 缺陷 1/2 修复边界（任务 3/4 判定）

| 端类型 | 探针结论 | 修复边界 |
|---|---|---|
| U3/U7 引脚区（0.4 脚距） | 双 via 物理不可能；F.Cu L 形直连 ✅ | **新增 F.Cu 直连逃逸形态**（无 via），删除"引脚区强制 via" |
| J2 连接器区 | via 间距 OK；落点被 pad 挡 | **via 落点列间空隙策略**（探针方向 ≠ 落点方向） |
| 电容墙区 | x 间隙 0.2/0.3 不能穿线；y 向/墙外可绕 | **pad 侧自适应方向 + 墙外锚定展开线** |
| MCIO 区 | CAPACITY_OK | 现有 via 逃逸复用 |
| 走廊段 | corridor_ok=True 全端 | 无缺口 |

**通道缺口（非算法可解，须方案级修输入）**：无——四类逃逸区均有物理出路，全部映射为"模型逃逸形态能力缺口"（缺陷 1）。J2 区 36 线双侧分摊需验证段级累积后仍可行（缺陷 2 关卡验证）。

# M13 v5 追加：容量地图交叉核对（2026-08-26）

## v5 结论（与 v4 §2.1 的关键差异）

v4 §2.1 判定"U3/U7 引脚区 F.Cu L 形直连 ✅ 可行"——**该结论为探针假阳性**：
探针只查"各自段 vs 障碍场"（P_ok/N_ok），**未查 P/N 段互交**（差分对内
豁免 + N pad 清出 → seg_ok 放行）。v5 实测：F.Cu 直连构造中 P/N 竖线
过渡段交叉（中心距 0.0000 → P/N 边缘距 -0.205）。

## v5 容量地图（模型 API，集合级证据）

| 区域 | v4 判定 | v5 实测（capacity_map.json） |
|---|---|---|
| U3/U7 引脚区 | F.Cu 直连可行 | flip 双极性几何不适配（pad 对在轨道带内）+ via 汇聚交叉 → 0~1/8 |
| J2 连接器 | 落点策略缺口 | GND 伴行 pad 压通道（d=-0.075）→ 0/8 |

| 走廊 | corridor_ok 全端 | 结构性受限（电源 pads 封端 + 电容墙挡轨）|

**几何粗算核对**：v5 会话 §2.3"空间富裕"证实（总面积/层容量无瓶颈）；
"相邻线边缘距 0.195≥0.175"证伪于**过渡段**（via/竖线汇聚处 -0.205）。
瓶颈 = 形态几何（0.4 pad 距 vs 0.38 轨距 vs 0.525 via 距三约束不兼容）。
