# hs_rebuild_v8 类 B 深挖：DN0/DN3/DN7 out_MCIO 逃逸竞争分类分析

> 任务：对 session_report §4.2 三条类 B 失败（out_MCIO 逃逸撞同链 out_U3 段落下的 via/seg，
> 及 DN7 撞 GND pad），用模型探针 + 读盘几何判定每处属 ①模型排序缺陷 / ②输入可修 / ③物理缺口。

## 1. 结论总览

| base | 判定 | v8 记录最近障碍（同链 out_U3/刚性件） | 距离 vs 需求 | 缺口 | 空场（无 out_U3）逃逸可解性 | 次级因素 |
|---|---|---|---|---|---|---|
| PCIE_DN0 | **① 模型排序缺陷** | via `PCIE_DN_OUT0_N_U3`（F.Cu） | **-0.1888** vs 0.175 | 0.3638 | ✅ **SOLVED**（flip=True） | 无 |
| PCIE_DN3 | **① 模型排序缺陷**（叠加逃逸形态缺口） | seg `PCIE_DN_OUT3_P_U3`（F.Cu） | **-0.1200** vs 0.175 | 0.2950 | ⚠️ 清空场 via 候选 4/4 过净空，但当前模型极性预检双 flip 拒（形态缺口，见 §3.2） | alloc `track_y=62.3` 拉长逃逸斜线 → P/N 相向交叉 |
| PCIE_DN7 | **① 模型排序缺陷**（叠加形态缺口；A19 GND 仅窗口塌陷后致命） | pad `GND`（F.Cu = J4.A19） | **-0.0750** vs 0.175 | 0.2500 | ⚠️ 空场窗口 18.15mm、via 候选 4/4 过净空，但极性预检双 flip 拒；Form A-纵向 下柱逃逸可避 A19（DN4 实证） | J4.A19 刚性 GND 脚（0.6mm 脚距内相邻脚） |

**统一机制**：同一 lane 的 `out_U3`（U3 TX→cap 段）与 `out_MCIO`（cap→MCIO 段）共享**同一走廊轨道带**
（alloc `seg_tracks`：DN0=58.7 / DN3=62.3 / DN7=67.1，两段同值）。模型按固定段序
`input → out_U3 → out_MCIO` 求解，`out_U3` 先解并把其逃逸几何（F.Cu pad→via 线段 + via + In2 段）
**立即提交为障碍**；而 `out_MCIO` 的逃逸起点（cap MCIO 侧 pad，与本 cap U3 侧 pad 仅 0.7mm 间隔）
需要**同一 via/轨道带** → 段间逃逸未协同，后解段无净空。空场（移除 out_U3 障碍）即可解 = 非物理缺口。

## 3. 逐网证据

### 3.1 PCIE_DN0 —— ① 模型排序缺陷（最干净）

**cap 两 pad 坐标**（0402，pad 0.4×0.5，cap 中心 @ x 行 y=57.8）：

| cap | U3 侧 pad（网） | MCIO 侧 pad（网） |
|---|---|---|
| C17（P 线） @ (76.800,57.800) | **(76.450,57.800)** `PCIE_DN_OUT0_P_U3` | **(77.150,57.800)** `PCIE_DN_OUT0_P_MCIO` |
| C18（N 线） @ (75.500,57.800) | **(75.150,57.800)** `PCIE_DN_OUT0_N_U3` | **(75.850,57.800)** `PCIE_DN_OUT0_N_MCIO` |

**out_MCIO 逃逸起点**：M = 两 MCIO 侧 pad 中点 = **(76.500,57.800)**，pn_dist=1.300（P/N cap 中心距），
dir=-1（右/ cap 侧逃逸，目标走廊 track_y=58.7，cv=(74.950,58.700)）。

**out_U3 via（先解段提交的障碍）**：P (76.813,58.302) & (76.45,58.51)；**N (75.513,58.302)** & (76.45,58.89)。
→ v8 最近障碍 = **via N @ (75.513,58.302)**，距 -0.1888，req 0.175，缺口 0.3638。
（该 via 距 out_MCIO 逃逸线 M→cv 仅 ~0.06mm 中心距；同时它使走廊轨道 y=58.51 的 `_corr_ok`
在 x<75.4 全部 -0.0424 失败，走廊窗口右缘被压至 74.95。）

**out_MCIO 逃逸候选坐标（空场，k=1..4 全部通过 fcu+esc 净空）**：

| k | p_via | n_via | pad_edge | 判定 |
|---|---|---|---|---|
| 1 | (76.787,58.302) | (75.487,58.302) | 0.300 | ✅ |
| 2 | (76.611,58.546) | (75.311,58.546) | 0.600 | ✅ |
| 3 | (76.436,58.789) | (75.136,58.789) | 0.900 | ✅ |
| 4 | (76.260,59.032) | (74.960,59.032) | 1.200 | ✅ |

注意 k=1 候选 (76.787/75.487, 58.302) **与 out_U3 实际落下的 via (76.813/75.513, 58.302) 几乎同位置**
——两段逃逸在数学上竞争同一 via 带（同一 pad 几何、同一 dvia 阶梯、同一轨道带）。out_U3 先占，
out_MCIO 全候选被 seg/via 挡（SHARED 最近障碍 seg `PCIE_DN_OUT0_P_U3`/`_N_U3` @ -0.12，via @ -0.1888）。

**窗口对比**：EMPTY [65.5,75.85]（10.35mm）→ SHARED [65.5,74.95]（9.45mm，右缘被 out_U3 via 压制）。

**判定**：空场可解（flip=True SOLVED）+ 唯一阻塞 = 同链 out_U3 提交的 via/seg → **①**。
非 ②：cap 坐标无异常（0.7mm pad 间隔为 0402 标准）；非 ③：DN1 同构（见 §4）可解。

### 3.2 PCIE_DN3 —— ① 模型排序缺陷 + 逃逸形态缺口

**cap 两 pad 坐标**（y=57.8）：

| cap | U3 侧 pad | MCIO 侧 pad |
|---|---|---|
| C23（P） @ (84.600,57.800) | **(84.250,57.800)** `PCIE_DN_OUT3_P_U3` | **(84.950,57.800)** `PCIE_DN_OUT3_P_MCIO` |
| C24（N） @ (83.300,57.800) | **(82.950,57.800)** `PCIE_DN_OUT3_N_U3` | **(83.650,57.800)** `PCIE_DN_OUT3_N_MCIO` |

**逃逸起点**：M = **(84.300,57.800)**，pn_dist=1.300，dir=-1，cv=(83.650,62.300)，track_y=62.3。

**out_U3 via（障碍）**：P (84.629,58.327) & (84.25,62.11)；N (83.329,58.327) & (84.25,62.49)。
→ v8 最近障碍 = **seg `PCIE_DN_OUT3_P_U3`（F.Cu，cap U3 侧 pad→via 线段 (84.25,57.8)→(84.629,58.327)）**，
距 -0.12，req 0.175，缺口 0.295。

**out_MCIO 逃逸候选（空场，k=1..4 全过净空）**：p_via (84.868,58.37)/(84.825,58.667)/(84.782,58.964)/(84.739,59.261)；
n_via (83.568,58.37)/(83.525,58.667)/(83.482,58.964)/(83.439,59.261)。

**窗口**：[65.5,83.65]（18.15mm）EMPTY 与 SHARED 相同（DN3 的 out_U3 逃逸在 x≈83.4-84.6 带内，未像 DN7 那样
压走廊左界，但直接挡在 cap 逃逸带内）。

**形态缺口（空场仍不可解）**：当前模型极性预检对 flip=False/True 均拒——
交叉点 (83.563,58.646)（flip=False，逃逸中段）/ (84.112,62.230)（flip=True，走廊入口）。
根因：corridor track_y=62.3 距 cap（57.8）**4.5mm**，逃逸斜线长 → P/N 相向交叉（min 边缘距 -0.2050，
即中心距 0.000 自交）。v8 模型无此预检，此类候选会在链级 `_pn_spacing_check` 以「P/N 间距不足」失败——
**同样不产生合法路径**。

**判定**：v8 记录失败点 = out_U3 seg 阻塞（① 主因）；空场叠加逃逸形态缺口（① 家族：逃逸模板无法覆盖
长斜线形态）。非 ③（无刚性障碍；DN1 同构可解）。② 次要：alloc 将 out_MCIO track_y 配 62.3（远离 cap）
加剧斜线形态；若轨道更贴近 cap（如 DN0 的 58.7 → 0.9mm）可缓解交叉（**方案级建议，未改 alloc**）。

### 3.3 PCIE_DN7 —— ① 模型排序缺陷（窗口塌陷）→ 触发 A19 GND；+ 形态缺口

**cap 两 pad 坐标**（y=68.0）：

| cap | U3 侧 pad | MCIO 侧 pad |
|---|---|---|
| C31（P） @ (84.600,68.000) | **(84.250,68.000)** `PCIE_DN_OUT7_P_U3` | **(84.950,68.000)** `PCIE_DN_OUT7_P_MCIO` |
| C32（N） @ (83.300,68.000) | **(82.950,68.000)** `PCIE_DN_OUT7_N_U3` | **(83.650,68.000)** `PCIE_DN_OUT7_N_MCIO` |

**逃逸起点（连接器侧，非 cap 侧）**：M = J4.A17/A18 中点 = **(64.000,61.450)**，pn_dist=0.600（MCIO 脚距），
dir=1（左/连接器逃逸，目标走廊 track_y=67.1，cv=(83.500,67.100)）。
J4 引脚：A17 (63.7,61.45) `P_MCIO`、A18 (64.3,61.45) `N_MCIO`、**A19 (64.9,61.45) GND**（0.3×0.7）、
B17/B18 (63.7/64.3, 63.95) UP7 P/N。

**out_U3 via（障碍）**：P (84.126,67.146)/(84.25,67.29)/(88.525,67.29)/(88.3,67.2)；
N (82.826,67.146)/(84.25,66.91)/(88.525,66.91)/(88.3,67.9)。

**关键机制 —— 走廊窗口塌陷**：

| 模式 | 走廊窗口 | 宽度 |
|---|---|---|
| EMPTY | [65.5, 83.65] | **18.15mm** |
| SHARED | **[83.5, 83.65]** | **0.15mm（塌陷）** |

塌陷根因：out_U3 N 的 **F.Cu 逃逸 seg (82.95,68.0)→(82.826,67.146)** 距走廊轨道 y=66.91 仅 0.24mm
（边缘距 -0.12），使走廊轨道在 x<83.5 全部 `_corr_ok` 失败 → 左逃逸锚点被迫推至 x=83.5。
于是逃逸线从 (64.0,61.45) 拉 19.7mm **浅斜线** 到 (83.5,67.1)（斜率 0.29）——在 x∈[64.75,65.05]
处以 y≈61.7 穿过 **J4.A19 GND pad**（中心距 -0.075 = 缺口 0.25）。
空场时锚点 x=65.5，斜线陡（斜率 3.77），x=64.9 处 y≈64.8 远高于 A19 → 不碰撞。

**out_MCIO 逃逸候选（空场，k=1..4 全过净空）**：p_via (63.874,62.104)/(63.951,62.394)/(64.028,62.684)/(64.105,62.974)；
n_via (64.474,62.104)/(64.551,62.394)/(64.628,62.684)/(64.705,62.974)。（沿 J4 引脚列下移，位于 A/B 排之间。）

**判定**：v8 失败点 = GND pad，但**仅因 out_U3 同链 seg 压塌走廊窗口**（① 主因）才被浅斜线撞上；
空场窗口下该障碍不致命，且 Form A-纵向「沿引脚列下柱 + In2 排间穿越」可绕开 A19（**DN4 实证**，
见 §4）。非 ③：连接器 0.6mm 脚距 + 相邻 GND 脚并非绝对不可逃逸（DN4 同排 SOLVED）。② 不适用
（A19 为连接器刚性脚，无法微调；cap 墙微调也解决不了连接器侧逃逸）。当前模型空场极性预检拒
（交叉点 (64.201,61.618) flip=False 脚间 / (64.324,67.077) flip=True 走廊入口）——形态缺口（① 家族）。

## 5. 修复建议（方案级，本次未实施、未改任何文件）

1. **① 模型（主修复）—— cap 逃逸单元化 / 段间逃逸协同**：
   将同链 `out_U3 + out_MCIO` 对**同一 cap 对**的两侧逃逸（4 个 pad → 走廊）作为**一个逃逸单元**联合规划，
   候选 via 按 DN1 实证的**垂直错开**（MCIO 侧 y 低于 U3 侧 y，或反序）枚举，段级净空互检后再提交。
   或：逃逸障碍仅在**走廊段提交**、cap 带内逃逸几何延迟到整链逃逸定稿后一次性提交（两段逃逸共享候选空间）。
2. **① 模型（次选）—— 求解序调整**：out_MCIO（连接器侧）先于 out_U3 求解，out_U3 长直走廊段绕让
   已提交的 cap 逃逸 via。对 DN7 需同时保留走廊窗口塌陷防护（窗口锚点不被同链段挤到对侧）。
3. **② 输入（可选加固，非本次失败主因）—— alloc `seg_tracks` 轨道贴近 cap**：DN3 将 out_MCIO track_y
   从 62.3 下调至接近 cap（缩短逃逸斜线，消除 P/N 相向交叉形态缺口）；DN0/DN7 轨道已贴近/可接受。
4. **② 输入（可选加固）—— cap 墙复摆间距**：若后续对 P/N cap 中心距（当前 1.3mm）与 pad 列间距
   （0.7mm）做微调（拉大 0.2-0.3mm），可进一步释放 cap 带逃逸余量；但 DN1 证明当前几何已可解，
   **不作为必要项**。
5. **禁止项**：不手补走线、不硬挤（0.175 净距是 DRC 铁律）、不 fallback（宪法第八章）。

## 6. 模型版本漂移（分析可信度边界）

- v8 求解器 sha `5464d8f0…`；当前工作区 `883525b4…`（`M eda_core/hs_route_model.py`，未提交）。
  diff = 类 A 修复：`_pn_ok` 极性几何预检（`_escape_pair` 内每候选构造即验 P/N 同层边缘距 <0.155 拒，
  带交叉点证据）+ 段组装 P/N 几何门（`_solve_pair_centerline_v4` 逃逸×走廊跨段交叉检查）。
- 影响评估：**当前模型 + v8 shared 状态对三条失败的重放与 v8 落盘逐字节一致** → 三条 v8 记录点稳健，
  本报告分类不受版本漂移影响（失败发生在净空检查路径，先于极性预检）。
- 差异仅出现在**空场**形态：DN3/DN7 空场经当前模型极性预检被拒（v8 模型无此检查，会产出交叉候选、

  不改变 ① 判定；但说明该类 A 修复虽捕获形态缺口，**未解决段间逃逸协同**（本报告 ① 主因），
  建议作为后续模型改进输入（§5.1）。
