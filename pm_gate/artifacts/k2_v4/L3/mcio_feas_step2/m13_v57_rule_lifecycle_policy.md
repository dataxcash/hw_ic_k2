# 规则生命周期政策 v1（ROOT-1）

> 目的：让规则**可学习、可演进、可扩展**，杜绝"有形无因"死规矩与一次性人工救火。

## 1. 每条规则的必备字段（缺一不可）
`id, statement(现状口径), origin(出处+可核引文), class(HARD|SOFT), purpose(目的/原因),
boundary(适用边界), relaxation_path(合法放宽路径), evidence(支撑/反例), revision(版本)`

## 2. 合法放宽路径（无人工救火）
1. **证据**：给出"原因在目标情形不成立"的可核证据（引文/实测/反例）。
2. **版本 bump**：修订写入**新文件**（`…_vN` 或 `…_revN.json`），旧件不动；改动 = 规则文本 + 边界 + 证据链。
3. **审批道（按层级，预设、无需逐次请示）**：
   - **项目工件层**（producer 参数、域工件、规则文本、作图规则）：**预授权**（本会话已行使：r2 域 ±2.5、R3 lane 序、F-13 r3 相干集）。
   - **冻结四源层**（SPEC/manifest/PCB/rules）：**须 owner**（本会话已行使一次：±1.5→±2.5 授权）。
   - **系统设计层**（层叠/平面用途/工艺）：**须 owner**，且须附 PD/SI 评估。
4. **回滚**：任何放宽必须可由"撤下新文件 + 指回旧版本"还原（本会话全部遵循）。

## 3. 硬约束（不可放宽，仅 owner；须在登记表中显式标注原因）
- 平面 In1/In3(GND)·In4(POWER) **不得作信号**（PD/SI 基础设施）。
- 6L 层叠与板厂工艺极限（JLC06161H）。
- 冻结四源原件字节（修订只在**新文件**层发生）。

## 4. 禁止事项
- 禁止产出不含 `purpose/boundary/relaxation_path` 的规则（"有形无因"）。
- 禁止把 A 情形的规则整域套用到 B 情形而不声明边界。
- 禁止以一次性人工授权替代本政策；同类项应登记为**预设审批道**。
- 禁止以未度量当已度量（度量缺口必须显式登记，见 C16/C17 先例）。
