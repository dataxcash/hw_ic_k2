## 0. 需要 owner 的一问（L1）
**J2 侧 `PCIE_REFCLK0/1` 的端点落在两列焊盘（P=奇/内列 11、29；N=偶/外列 12、30，同排 0.6 节距）**——
外列 N 无法向西穿越内列焊盘墙（见 §1.2），故 REFCLK 对在 J2 侧**必须拆对**（P 西出、N 绕连接器端部）且两条 refclk 对互相封堵，
**无法以「成对、等长、F.Cu 单层」布线**。请裁定：
- **(A)** 允许 J2 侧拆对 + 绕行拓扑（则需 W0-R 见证件 v2 输出接入窗口 + 引擎新布线族，属独立 L2 周期，见 §3）；或
- **(B)** 重定 J2 侧 REFCLK 引脚（改到**同一列**相邻焊盘，如内列 11/13 或外列 12/14）⇒ P/N 均可直接西出（与数据对 P 侧同理），绕行与互封问题同时消失。
  ⚠ (B) 需改**冻结源** `k2_v4_8L.kicad_pcb` 的网表（REFCLK 引脚分配）⇒ 属 **L1（球/引脚重映射）**，且与「不改四源原件」红线相关 ⇒ 必须 owner 授权后走版本化 ECO。

J2 = 2 列 × 37 排（y=42.9…64.5，0.6 节距；奇数=内列、偶数=外列）⇒ 每对跨两列，与数据对同构（数据对亦为 P 内列西出 / N 外列东出，如 `DN0/input` P x=125.85、N x=142.38）。
**端点来源**：manifest 记 `s0_method_net_join(REFCLK 第二端补录)`；`m13_v57_s0_endpoint_model.json` 的 `connector_audit` **只有 J3/J4 的 `conn_pin: REFCLK_P/N` pass-through 条目，无 J2 侧 REFCLK 引脚审计** ⇒ J2 侧引脚选择属**模型补录**（未经连接器引脚审计）。

### 1.2 内列焊盘墙 = 物理不可穿越（决定性）
内列同排相邻焊盘间隙 = `0.6 − 0.35 = 0.25 mm`；0.205 线宽所需最小中心通道 = `0.205 + 2×clearance`。
即使用 SPEC 逃逸区下限 `clearance = 0.075` ⇒ 需 **0.355 mm > 0.25 mm** ⇒ **外列 N 在任何 y（除焊盘场两端之外）都无法向西穿越内列**。
（唯一东西向通道为两列之间的缝 `x≈133.825`，宽 1.05mm；但它被内列墙夹住，仍然出不去西侧。）

### 1.4 后果（为什么「成对布线」不成立）
1. **N 必须绕连接器端部**：`REFCLK0_N` 需绕北（y≈42.4），`REFCLK1_N` 若绕南（y≈65.2）则其上升段与 `REFCLK1_P` 的下降段必交；若绕北，则其南下穿越段**必穿 `REFCLK0` 对的东西向带（y≈44.31/44.69，x 58.3…132.65）**。
2. **对与对互封**：`REFCLK0` 的 F.Cu 东西带横跨全板宽 ⇒ `REFCLK1_N` 无从北向南穿越（除 x 两端，而东端 x>135.65 被其他网逃逸占满、西端 x<53 需再绕 J3 场）。
3. **同对内也不成对**：J4 目标行在北、两轨在南、两焊盘同排并列 ⇒ 若两线同侧进线必违 inside-corner；反向进线则在焊盘下降段交叉（本会话已穷举 4 种轨分配/进出侧组合，均交叉）。
4. **无换层退路**：SPEC `decision_contract.refclk_layer = F.Cu(D0-2)`（冻结）⇒ 不能借 In2/In6/B 绕过。

## 2. L2/L1 判定
- 几何（走廊/轨道/过孔策略）= **L2**，本会话已把可行通道全部测清（§1.3）；
- 但**「REFCLK 对在 J2 侧拆对、绕行、长度差 ~10mm 以上」**属**接口/信号流向**层面的形态决定（差分参考时钟对在连接器处分对）；
- 且端点的引脚选择本身是**未审计的补录**（§1.1）——是否维持 11/12、29/30 = **球/引脚重映射 = L1**。
⇒ 以红线「L1 才需 owner」与监督指令「确属 L1 ⇒ 一句话说明并停」：**本项停候 owner 裁定 §0 的 (A)/(B)。**
