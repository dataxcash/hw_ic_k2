# m13 v56 — 施工方案模块完整修复方案（依据 v55 复查报告）

> 前置文档：m13_v55_construction_module_review.md（缺陷 A1/A2/B1/B2/C1/C2/D1/D2/E1/E2/E3）。
> 本文给"为什么这版修复可行 + 每阶段如何证明可行 + 如何验收"，按依赖拓扑排序。
> 设计原则（全部源自讨论裁决）：
>   1) 施工图先于施工（reservation-first）；DRC 是结果验证，不是图纸审核。
>   2) 生成即合法：生成器只消费登记簿，能生成即合法；生成不了 = 明确 INFEASIBLE+证据，
>      绝不吐坏图。审核退回安全网位，不是救命稻草。
>   3) 可行性在生成端证明：每阶段开工前先交"存在性证明/证实实验"，过了才准编码。
>   4) 单一事实源、顺序无关、无后推（禁止以"已知账/另卡处理"作为阶段出口）。

- **不做什么**：不动任何求解/分配逻辑。

## P1 数据形状与覆盖（图纸输入无歧义）
- **开工前证明**：先跑证实实验——U3/U7 区补 corridor 锚后 landing 能否为芯片侧
  failing 网（UP0-7/out_MCIO）产出行；若产出行 → 覆盖断裂坐实，本阶段目标可达。
- **内容**：
  1. SPEC band.nets(list) 与 ChannelInput.nets(str) 形状统一（择一契约），
     删除 nets_path 覆写；_alloc_nets 拒绝伪网名（出现即 raise）。
  2. 区域归属重划分：MCIO/U3 重叠窗口（x∈[74,90]）改为**不相交所有权分区**
     （pad→region 归属断言：每 pad 恰好一个 region，重复/遗漏即 raise）。
  3. U3/U7 region 补 corridor 锚（映射到 EAST_CHIP_TO_J2 / WEST_MCIO_TO_CHIP 的
     正确 band），使芯片侧出逃列可被分配器认领。
- **验收（可证伪）**：U3/U7 两区 assigned>0 且无 pad 归属二义；无 nets_path 覆写；
  全 34 网 pad 归属闭包完备（每片需要逃逸的 pad 都有唯一 region）。
- **不做什么**：不改分配算法本身。

## P2 登记簿接线（先登记后展开从纸面变数据流）
- **开工前证明**：对现 18 失败 lane 用 escape_allocator 做**正向规划试跑**
  （不许反演已解路径），预期能为其列分配产出 ASSIGNED 或带超卖证据的 NO_ESCAPE；
  该试跑先于接线在独立脚本验证，结果决定接线可行性。
- **内容**：
  1. column_book/escape_table/escape_allocator 接入 solve_pipeline（阶段④b：在
     escape_landing 后、solve 前，对**全部**需逃逸 pad 出预留行）。
  2. 阶段⑤ hs_route_model 改为**消费登记簿**：每 lane 的 via 位置 = 簿中
     ASSIGNED 行（fail-closed 语义升级为"簿外一律不可画"）；**废除自搜 fallback
     族**（_sym_via 锚线自搜 → 只读簿；_pad_row_dip/_col_stack 等保留为"簿内
     形态"而非"自搜逃生口"）。
  3. 验收语义变化：ASSIGNED 行展开交叉 = 引擎 bug（红级），不是 INFEASIBLE。
- **验收（可证伪）**：管线跑完，每失败 lane 的原因只能是"图上未预留
  （NO_ESCAPE+超卖资源证据）"或"簿内展开 bug"两者之一；-0.2050 类 reason
  在失败集中绝迹。
- **风险与回滚**：若 18 lane 正向规划大量 NO_ESCAPE → 说明是 P3 全局层容量问题
  而非接线问题，P2 保持簿架构、容量冲突移交 P3，不回滚接线。

## P3 全局可行性层（真正的施工图第一段）
- **开工前证明**：顺序敏感性实验（最小证实实验 A2）——倒序/密度优先重跑现管线，
  若失败集变化则证明"需要全局层"；全局层的正确性以"分配序无关"为判据。
- **内容**：
  1. 在 P2 簿之上加"先算后画"：一次装载全部 demand，按**全局密度/灵活度**
     （least-flexible-first）而非网名排序做预留；预留阶段即完成 lane×资源
     的联合指派。
  2. 簿写冲突即全局不可行：输出 INFEASIBLE-manifest（哪块资源超卖、哪几条 lane
     竞争），这是图纸级的正确结论，**先于任何铜展开**。
  3. 展开阶段成为纯机械：资源独占，理论上零冲突；残留冲突视为 bug 并当场红级。
- **验收（可证伪）**：
  - 同输入、任意确定性 lane 枚举序（正/倒/密度序），solve 失败集与路径逐字节一致
    （顺序无关达成）；
  - 展开阶段冲突数 = 0；若 >0，必须是登记簿 bug 并当场修簿，不许落到 lane 头上；
  - 全局 INFEASIBLE（若有）能指向守恒级证据（容量/跨度/极性硬冲突），并可与
    alloc/SPEC 输入直接对账。
- **不做什么**：不动板文件/SPEC/宪法（本层以上层产出为输入）。

## P4 分配器自洽硬化（与 P3 并行）
- **开工前证明**：对 133.825 家族做簿写回放——断言同列最小间距后分配器是否仍能
  完成该区指派（若否 → 冲突为真容量问题，需上 P3 密度序；若是 → 同列自检可达）。
- **内容**：
  1. ColumnBook/landing 写入期强制同列/同格密度自检（133.825 家族在分配期拦截，
     带最近冲突行证据）。
  2. D3 极性：ASSIGNED 行 polarity_consistent 必须为显式 bool，禁止 None；
     非 true 即 raise（把纸面断言变机器断言）。
  3. 区域交叉（跨 region 相邻列）冲突也在簿层可见（簿是全局的，不再按区隔离）。
- **验收（可证伪）**：任一次预留快照零同列违例、零 unchecked 极性；
  133.825 家族不再出现于消费期 fail-closed。

## P5 学习回写 + 单调收敛闭环（封环）
- **开工前证明**：KB/matcher 命中率基线（对 34 lane 失败特征签名检索，
  记录当前命中数）——证明回写机制的起点。
- **内容**：
  1. 强制学习回写：每张"图"（P3 manifest / P2 簿 / 终局铜）及每条 NO_ESCAPE 的
     几何特征签名 + 结果入 KB；分配器/形态选择先查库后决策（命中则复用，
     未命中须写理由）。
  2. 单调收敛规则：**每阶段结束，全局失败集只许收缩、不许平移**；新增失败必须
     在本阶段内闭环，禁止"另卡处理"出口；32 段字节稳定性按声明范围锁定。
  3. 报表按段级度量（弃整 base 的 solved_pairs 全有全无口径），保留 per-seg 明细。
- **验收（可证伪）**：v56 各阶段结束快照对比 P0 基线：34 段失败集单调不增；
  KB 命中数单调上升；两次 run_all 字节一致持续成立。

## 关键取舍声明（需负责人背书）
- P2 废自搜族后，形态（col_stack/dip/LSWAP 等）从"逃生口"转为"簿内形态"：
  簿给出 via/列，形态只负责在预留内机械展开——这是架构语义迁移，不是删能力。
- P3 若产出全局 INFEASIBLE 于若干 lane，那是**正确的答案**（图纸不存在），
  其处置走容量/拓扑决策（换层/改分配输入），不是施工层兜底——与现行
  "施工层把不可行当 bug 修"相反。
