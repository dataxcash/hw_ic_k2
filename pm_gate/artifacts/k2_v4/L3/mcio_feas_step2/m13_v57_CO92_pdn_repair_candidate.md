## 1. 立件理由（对 CO-91 的一处**作废**）
CO-91.1 内嵌的 `fix_candidate` 用「8 向 × 半径梯 0.30–2.00」搜索求合法位，报出 **35/35 可重定位、0 blocked**。
该形式**违项目红线「零坐标搜索 / 一次求解」**（v56 P2「施工禁自搜」亦指向同一原则），且其解不是任何**声明策略**，
等于用求解器回答设计问题。**该字段已作废**（CO-91.3 移除，指向本件）。本件以**可采纳的声明式有限 palette** 重算。

## 2. 方法（无搜索、单一语义来源）
- **候选 palette（声明固定，确定性序）**：
  - ppc：**原位** → 自家 pad 的 **4 正交点 @ (VIA_R+0.3)=0.475**（= 生成器现行策略）→ **4 正交点 @ 0.6**（备用）。
  - stitch / zone：**原位** → **4 正交点 @ 0.6**。
  - 择优规则：**优先原位**（零位移）；否则取「可达者中余量最大」。无迭代、无连续量搜索。
- **判定器**：直接复用 CO-91 的权威检测器（`drc_rules` 语义核 + 层语义 + 精确几何）⇒ 单一语义来源，避免两套口径。
- 规则源唯一性断言（fail-closed）同 CO-91。

## 4. 解读（关键：这不是「纯重定位」问题）
1. **ppc**：34/223 无任何声明 palette 内的合法位 ⇒ 这 34 条**必须改为 `blocked`**（诚实处置），
   或改走 **via-in-pad / 平面直连**。**决策覆盖不退化**（每个板实 pad 仍有决策 = 309/309），但**已连接数 223 → 189**。
   残余 34 与 CO-91 的 U6 密集场结论同源 ⇒ 属**工艺/口径裁决**（需 owner/PM + 板厂 VIP 能力），**非引擎可自解**。
2. **stitch**：12 可移、29 须 blocked（现行 SPEC 已有 31 例显式 blocked，属同类处置）。根因：`gnd_stitch_gen`
   的障碍集 = `layer_plan` 的**规划段**，**不含交付板实际铜**（v57 改用 In5 走线、F.Cu REFCLK 后即漂移）。
3. **zone**：4 可移、3 须 blocked；另 `power_zones[].vias` 的**派生来源未在仓内标识**（记录无 ref/pad）⇒ 重派生前须先定位其生成器。
4. **短段宽度**：把 0.5mm 声明改为与节距相称（≥0.2 可制造）可把 75 → 13 违规；**残余 13 全在密集场**，与 (1) 同源。

## 6. 附（本件另发现，登记不擅改）
- **`gnd_stitch_gen` 输出与消费者 schema 不一致**：其 blocked 记为 `ok: False`（且**仍带 x/y**），
  而 `pdn_apply.py` 只跳过 `c.get("blocked")` 或 `status=="blocked"` ⇒ 若直接重跑该生成器，
  **blocked 缝合 via 会被实落到板上**。现行 rev-9 用的是 `status: blocked` 形态（故暂未触发）。修 rev-10 时必须一并对齐。
- **`pad_connect_gen` 无 hole_clearance 概念**、且**跳过全部 via**（详见 CO-91 §4）。
