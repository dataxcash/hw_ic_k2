## 0. 背景与动机

### 0.1 v1→v3 演进

| 版本 | 走廊段 | 逃逸段 | 结果 |
|---|---|---|---|
| v1 | V-Graph 全图搜索 | V-Graph | UP4 超时、REFCLK1 102s |
| v2 | 确定性折线 + 对中心线 + P/N 展开 | 死代码（AttributeError） | 逃逸触发即崩 |
| v3 | 确定性折线（同 v2） | In2 换层 L 形折线 | 18/18 SOLVED 0.2s，**落板暴露缺陷** |

### 0.2 v3 落板验收失败（现象）

全量 18 对在真板 k2_v4 求解 SOLVED（0.76s）→ 落板到副本 → kicad-cli DRC：

- 高速网违规 **1037 条**（落板前 0）
- 高速未连接 4 条

**2026-08-25 实测补充（v4 探索期发现）**：v3 的 solve_all_v2 输出 P/N **无 layers
字段** → hs_apply 落板全部 skip（nets=0 tracks=0）→ 旧协议下"落板副本 DRC 1037"
的证据链不完整。v4 引擎（solve_pair_v4）必须输出 **path + layers**（落板协议），
关卡测试以 hs_apply skipped=0 为前置断言。

### 0.3 根因（v4 必须修复的 4 类缺陷）

**缺陷 1 — P/N 逃逸不对称（同对短路）**
逃逸段 P、N 各自独立求解折线 → 路径不同 → 差分间距被破坏。
证据：`UP5_N vs UP5_P`、`UP2_N vs UP2_P`、`DN_OUT1_U3` 等同对短路 26 条 + diff_pair_gap 5 条。
根因：走廊段用了"对中心线 + ±0.19 对称展开"，逃逸段偷懒没沿用。

**缺陷 2 — 无段间互检（相邻对逃逸交叉）**
每段独立建场，场把高速段全部清出（重建语义）→ 新段互不为障碍。
证据：`UP_OUT0_N_J2 vs UP_OUT1_P_J2`（10 条）、`REFCLK1_N vs UP_OUT6_P_J2`（10 条）。
根因：逐段独立求解，无"已解段累积"机制。
**机制性根因补充（v4 实测）**：
- a) 累积障碍必须**段级清出**：clear_hs_pads=True 把全部 HS pads 清出 → 先解段
  的 F.Cu 短段穿过后解段的 pad（U3 输出区 out_U3 短段穿 out_MCIO pad）→ 后解
  段无路。场构建须只清本段 P/N pads（clear_hs_nets），他段/他对 pads 保留为障碍。
- b) v3 落板协议断裂（见 §0.2）：无 layers → 落板空转 → 段互撞以"真板残留"形态
  出现在 DRC，非新落线段形态。

**缺陷 3 — PDN 让位 vs 落板不同步（高速穿 GND 铜 277 条）**
模型让 PDN 让位（yield_pdn=True，路径穿过电源区——硬需求，实测 False 时 8 对无解），
但落板只画高速段、不删被穿越的 PDN 段 → 短路/间距违规。
归属：S3 PDN 铺铜接管（三域联动 PM 已授权"PDN 让位"），但落板必须同步登记/删除。

**缺陷 4 — REFCLK 端点断连（4 条）**
REFCLK0 In6 走廊段端点与 J3 焊盘未连接（F.Cu 短段/换层 via 连接问题）。

### 0.4 为什么会出现（反思级根因）

验证标准错误：把"每条线 SOLVED + 快 + 单测过"当成功——全是**单线局部正确性**。
从未把 18 对路径放同一张图检查互撞。局部都对、合起来错 = 验证等于没验证。
**v4 第一原则：整板一致性是硬验收，与单测同级。**

> 把人类硬件工程师的物理规划思路固化为七步法，写入 AGENTS.md §5 硬约束，**禁止违反**：

1. **先画图后算数**：动手前先手工画出受影响区域实际几何（pad 位置/尺寸、走廊、
   via、已解段坐标），量出关键尺寸；未理解物理几何前禁止修改算法参数。
2. **先单条后全量**：先手工规划一条完整链路（连接器→走廊→芯片→电容）逐段确认
   净空与可行，单条验证通过才扩展；禁止直接全量求解。
3. **先算容量再布线**：瓶颈区（引脚/电容/连接器）先算逃逸容量
   （线宽+净距+via ≤ 可用宽度）；容量不足 = 方案级缺口（通道/错层/布局）。
4. **失败带证据**：INFEASIBLE/违规给出物理证据（最近障碍类型/网/距离/对比）；
   禁止无证据"改参数重跑"（同输入重跑 ≥2 次即暴力迭代）。
5. **先理解现象再修改**：修改前先定位现有落板结果实际几何（哪条线在哪交叉、
   最短距离），用证据指认缺陷。
6. **问题 = 模型改进机会**：每个失败映射到模型/输入缺口（通道分配/约束描述/
   算法能力），修复 = 升级结构描述 → 升级算法 → 验证；禁止 workaround。
7. **验证闭环**：每处修改先验证受影响单条链路（单对 <5s、净空、层协议完整），
   再全量；证据落盘（路径坐标/净距/容量计算）。

## 1. 基本原则（布线方法论）

1. **对称优先**：差分对 P/N 永远同一中心线 ±0.19 对称展开（间距恒 0.38、长度恒等）。
   走廊段、逃逸段统一。P/N 各自独立求解 = 非法。
2. **确定性**：候选序、滑动步长、求解顺序全部固定 → 同输入永远同输出，零随机零迭代。
3. **主路径确定性折线，搜索仅兜底**：L 形/45° 折线逐段验证（H-V/V-H/DIAG + 滑动，
   O(段数×障碍数) 毫秒级）；V-Graph 仅最后单次调用；禁止"多候选×全图搜索"嵌套。
4. **累积障碍**：已解的线是后续段的障碍（自己人也躲）——后解让先解，顺序固定即结果唯一。
   **段级清出**：障碍场只清本段 P/N pads（clear_hs_nets），他段/他对 pads 保留为障碍
   （先解段不得穿过未解 pad——v3 缺陷 2 的机制性修复）。
5. **分层验证**：每层独立场独立验证（F.Cu 短段查 F.Cu 场、In2 段查 In2 场、
   走廊段查 band 层场），杜绝层混叠。
6. **整板一致才算成功**：局部可解 ≠ 成功；18 对同画 0 冲突是硬验收（自动化关卡）。
7. **落板协议完整**：模型输出 path + layers（每段一层，len(layers)==len(path)-1），
   层变点即 via；hs_apply 落板 skipped=0 是关卡前置断言。

## 2. 布线顺序（固定、可复现）

顺序设计的依据：**越晚解越被动**（障碍越多），所以先解链路主体，自由绕行区最后收口；
通道独占的先占位。

```
[通道分配] 18 对占 track_y 通道（channel_alloc，已做；REFCLK In6 独占通道）
  ↓
[对级顺序] UP0→UP7 → DN0→DN7 → REFCLK0→1（固定数字序，solve_all_v4 强制）
  ├─ 走廊段通道隔离（track 间距 1.08mm），顺序无关
  └─ 逃逸段按序累积障碍——后解绕先解（引脚区密集）
  ↓
[段内顺序] input → out_U7/out_U3 → out_J2/out_MCIO
  （长段先解占位，短段后解）
  ↓
[段内部] 走廊段（track_y 固定，先）→ 逃逸段（自由绕行区，后收口）
```

**通道分配事实（v4 实测）**：channel_alloc 按 base 分配（alloc 键 = PCIE_{base}，
18 键），**同 base 多段（input/out_U3/out_MCIO）共享同一 track_y**。UP 8 对占满
upper 8 轨（40.92-48.48）、DN 8 对占满 lower 8 轨（58.92-66.48）、REFCLK 2 对
占 refclk 2 轨（In6）——**无空闲轨道**。因此逃逸区（U3/U7 输出、电容、连接器）
的容量是硬约束：同 base 段的逃逸必须共享引脚区，段级清出 + 后解绕先解是唯一出路；
若物理容量不足 → INFEASIBLE 带证明（禁止算法硬挤、禁止换轨）。

## 3. 约束体系（检测什么 + 怎么控）

| 约束 | 阈值 | 检测控制点 |
|---|---|---|
| 高速↔高速净距 | 0.175mm | 每段候选逐段 seg_ok |
| 高速↔低速段/via | 0.175 / hole 0.25 / mask 0.05 | 同上（DRCRuleLibrary 自动派生） |
| P/N 对内间距 | ≥0.1mm | 对称展开构造保证 |
| 差分对间距 | 0.38mm（0.205 宽 + 0.175 gap） | 构造性（±0.19 展开） |
| 走廊通道 | track_y ±0 | 走廊段固定走分配通道，不侵邻道 |
| via 每线 | ≤2 个（单次换层往返） | 逃逸受控 via 落位 |
| via 不落焊盘 | 距 pad 边 ≥0.3mm（no_via_in_pad） | F.Cu 短段（pad→0.3mm 外 via） |
| via 对称 | P/N 对称落位（±0.19） | 对级逃逸构造 |
| 链路等长 | skew <0.15mm | 段级对称 + 链级蛇形补偿（确定性） |
| 端点闭合 | 精确相连 | 段验收强制（F.Cu 短段起点=pad 中心，段端点=via） |
| 段间互检 | 已解段净距 0.175 | 累积障碍场（段级清出 + shared_segs） |
| 段级清出 | 本段 P/N pads 清出、他段/他对 HS pads 障碍 | build_hs_field(clear_hs_nets) |
| 落板协议 | len(layers)==len(path)-1 | 段输出校验 + hs_apply skipped=0 |

**控制流程（每段）**：
1. 候选生成（固定序：H-V/V-H/DIAG + 中心线滑动）
2. 逐段分层 seg_ok（对应层场 + 已解段累积 + 段级清出）
3. 全部约束过 → 接受；否则下一候选
4. 候选全失败 → **单次** V-Graph 兜底（对级中心线）
5. 仍失败 → **INFEASIBLE 带证明**（连通分量 + 边界障碍清单，nearest_obstacle
   证据：最近障碍类型/网/距离）——禁止重试/迭代，判定缺口 → 方案级修输入

## 4. 求解管线（数据流）

```
输入(RouteInput: 板/SPEC/通道分配/规则)
 → [0] 输入校验：端点完整性 / 通道分配存在性 / 规则加载
 → [1] 通道分配（channel_alloc，既有；同 base 段共享轨道）
 → [2] 顺序编排（§2 固定序：UP→DN→REFCLK × input→out）
 → [3] 每段求解（solve_pair_v4 → K2 走 _solve_pair_centerline_v4）：
      a. 建场：band 层场 + F.Cu 场 + In2 场
         （clear_hs_pads=True + clear_hs_nets=(本段 P/N) 段级清出）
         + 已解段 shared_segs 进各层场（add_seg，高速↔高速互检）
      b. 走廊段：对中心线（track_y 固定 + 端点滑动）+ _expand_pair ±0.19
         + 分层 seg_ok
      c. 逃逸段（对级对称，缺陷 1 修复核心）：
         1) 对中心线 = P/N pad 对中点 → 走廊起点，确定性折线候选
            （H-V/V-H/DIAG + 0.3mm 滑动，固定序）
         2) pad 侧自适应展开（_escape_expand）：P 展开落在 P pad 侧
            → F.Cu 短段短、不横穿对侧；P/N 仍关于中心线对称（0.38 构造）
         3) 终点强制回正：P 终点 = (sx, track_y+0.19)、N = (sx, track_y-0.19)
            （走廊 P/N 线衔接，杜绝 P/N 错位）
         4) 对称 via = pad 沿走廊方向外移（pad 半投影 + 0.3mm 阶梯）
            → F.Cu 短段垂直 pad 面、最短；via 两场净空 + 距 pad ≥0.3
         5) In2 段 = via → 展开线垂足（锚定展开线，P/N 同弧长对称）
            → 走廊端点，分层 seg_ok
         6) F.Cu 短段（pad→via）+ In2 段 + 走廊段 逐段分层 seg_ok
      d. 段验收：P/N 对称（间距 0.38 构造）/ 端点闭合 / via 规则
         / layers 协议（len==path-1）
 → [4] 链路验收（solve_chain_v4）：总长等长 skew<0.15 → 蛇形补偿
      （确定性，最长走廊段承载，layers 同步）
 → [5] 全局验收（solve_all_v4）：18 对全 SOLVED + 段间互检（累积障碍下）
 → [6] 落板（hs_apply v2）：删该网旧段/via → 落新段+via → 删让位 PDN 段
      （登记清单）→ 保存
 → [7] 整板验收：kicad-cli pcb drc（--severity-error --refill-zones）
      → 高速网 0 违规（硬关卡）+ hs_apply skipped=0
 → [8] 记录：solve_ref + input_fp + 路径/等长/容量证据 → model_solves/hs_rebuild/
```

**段级清出与累积障碍的关系（v4 实测结论）**：
- clear_hs_nets=（本段 P/N）：本段 pads 清出（连接对象），**所有其他 HS pads
  保留为障碍**（含同 base 其他段的 pads）——先解段必须绕开未解的 pad，杜绝
  "先解段穿后解 pad → 后解段无路"的缺陷 2 机制性死锁。
- shared_segs：已解段（含本链前段）逐段 add_seg 进对应层场——后解绕先解。

## 5. 确定性保证

- 唯一状态 = 已解路径集合；顺序固定 → 每个候选的成败唯一 → 全流程结果唯一
- 零随机、零迭代（单遍求解，失败即证明性 INFEASIBLE）
- 复杂度 O(段数 × 障碍数)，毫秒~秒级，全程无暴力搜索嵌套
- 失败判据：单对 >5s 即暴力求解嫌疑，停转 Plan

- 关卡语义：整板一致 = 高速域 0 违规；INFEASIBLE 段不落板（保持真板原状），
  其残余违规计入证明性报告（PDN 冲突登记 S3），不掩耳盗铃

## 7. 实现任务分解（v4 session 用，按七步法重排）

0. **天条启动**：读 AGENTS.md §5 人类老工程师七步法（先画图→先单条→先容量→
   失败带证据→先理解现象→问题即机会→验证闭环），全流程遵守
1. **关卡先行**：写整板一致性测试（solve_all_v4 + path/layers 协议校验 +
   hs_apply skipped=0 + DRC 断言）——v3 状态 FAIL（锁缺陷）
2. **手工规划单条链路**（七步法 1/2/3）：坐标级手工规划 DN0（或 UP0）完整链路
   （J2→U3→走廊→电容→MCIO），量出 U3/U7 输出区、电容区、J2/MCIO 连接器区
   的逃逸容量（线宽+净距+via vs 可用宽度），输出 capacity 分析报告
   （证据落盘）——这是缺陷 1/2 修复的物理基准
3. **缺陷 1**：对级对称逃逸（_solve_pair_centerline_v4：对中心线 + 自适应展开
   + 终点回正 + via 紧贴 pad + In2 锚定展开线）；删除 P/N 独立逃逸路径
4. **缺陷 2**：累积障碍 + 段级清出（clear_hs_nets + shared_segs 进各层场）
5. **缺陷 3**：hs_apply 落板删让位 PDN 段 + 登记清单（→ S3 铺铜接管）
6. **缺陷 4**：REFCLK 端点（In6↔J3/J2 连接，F.Cu 短段/via）
7. **全量验收**：18 对落板副本 → 整板 DRC 高速 0 违规（关卡绿）→ 落真板
   → 真板 DRC 复验（高速域目标 0 或带证明残余，PDN 冲突登记 S3）
8. **正规流程**：model_gate 验证（SPEC 高速段 100% solve_ref）→ sregress S2
   → 施工层落板 → sadvance S2 → S3 PDN 前置登记
9. **交付**：代码 + 单测全绿 + 关卡绿 + 求解记录更新 + 落板报告 + 容量证据
   + 状态机记录
