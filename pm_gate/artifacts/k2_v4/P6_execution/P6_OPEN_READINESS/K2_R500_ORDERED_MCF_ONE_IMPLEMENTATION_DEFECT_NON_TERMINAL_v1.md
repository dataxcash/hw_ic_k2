## 一、**具名缺陷（可复现）**
复用的格网边表（`R499` 件 `_build_edges`）对每条边**只存一次**、且取向为「flat index 递增」（其自身 Dijkstra 把它当**无向**用：
`csr` 里同时放 `(u,v)` 与 `(v,u)`）。本件把该表当**有向弧**用 ⇒ `fwd(src) ∩ bwd(snk) = ∅`
（**出闸北上的那一跳是 flat index 递减**，有向图走不到）⇒ **弧集被裁成 0 条/网** ⇒ 模型退化（1 变量）⇒ 求解 0.0s 空解 ⇒ 提取 0 条。
**根因 = 弧向处理错误**（实现缺陷），**非**范式无效、**非**板不可行。

## 二、由此得到的**结构性结论**（下一版必须带上）
1. **必须对称弧**：正确 MCF 需对每条无向边开**两个方向**的布尔（且 `x_uv + x_vu ≤ 1`）⇒ 以现节点集计约 **6.4e5 布尔** ⇒ **必须配套降规模**（本轮未做）：
   - 逐网**双向** on-path 裁剪（正向可达 ∩ 反向可达，**无向**定义）；
   - 端区收缩（A 条带 / B 条带 各自先收缩成单点）；
   - 仅对**存在对角弧**的胞加局部净距约束（其余胞最近距离恰 0.435 = 允许值）。
2. **净距约束已备好**（本件已写对）：8 邻格下 <0.435 的形态**只有 5 类**（对角弧↔邻点 ×4 ＋ 两对角弧互交），逐胞 5 条**线性**约束即**完备**覆盖 ⇒ 无需 forbidden-pair 表。
3. **4 邻域不可行**（实测 16/16）⇒ 任何"Manhattan-only + 节点/弧容量"的简化都会产出**假不可行**，禁用。
