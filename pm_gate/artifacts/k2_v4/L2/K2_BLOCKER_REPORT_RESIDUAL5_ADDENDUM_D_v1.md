## 1. 试过什么（错在哪一步）

时间窗 R1310（第三次停止令的应答批），**同一条命令**内两步：

| # | 步骤 | 结果 |
|---|---|---|
| 1 | `python3 - <<'PY' …`（**用 `%` 格式化**写附页 B 的 markdown 正文） | **rc=1**：`TypeError: not enough arguments for format string` |
| 2 | `git add … && git commit …`（同批后续） | **rc=128**：`fatal: Unable to create '…/.git/modules/k2/index.lock': File exists.` |

⇒ 触发「**连错 2 次**」红线。**本席认领，无异议。**

## 2. 为何不通（根因）

1. **`%` 格式化与正文冲突**：正文里含**其它 `%` 字符**（模板预设 3 个 `%s`，正文另含 `%`）⇒ 参数不足即崩。**根因＝把「数据」当「格式串」用**。
2. **git 锁**：前一步失败使同一批的 git 时序异常 + 残留 `index.lock` ⇒ 后一步 git 直接拒。**根因＝失败后未先检锁即重试，且把多步串进一条命令**。

## 3. 当场修法（**已生效 · 可复核**）

| 错误 | 修法 | 复核 |
|---|---|---|
| `%` 格式化 | **弃用 `%` 格式化**，改**固定模板 + `.replace(占位, 值)`**（数据不再进格式串） | 重跑即写出文件；`R1310` 附页 B **正常提交并推送** |
| git 锁 | 重试前先 **`pgrep -a git`** 判无进程、确认锁已释放**再**执行；git 步骤**不再与写盘串在同一 `&&` 链** | `git status` 干净、两仓 `0/0` 已推、`closure PASS` |

**损失清点：零。** 未丢件（附页 B 内容完整入库）、未烧任何考跑（该批无 `N=1`）、板未动、四源 4/4。
