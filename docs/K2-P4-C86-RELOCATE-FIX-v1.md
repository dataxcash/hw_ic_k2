## 1. 落位（为什么是这一点）

重落位约束 = 原落位解 `constraints`（`inset 0.3 / pad_clearance 0.2 / part_spacing 0.5 / hole_keepout φ6`）
**+ 新增「既有封装本体不得重叠」**（这正是 D-1 的根因缺口）。free-space 网格 0.1 mm 实测可行位 193,760 个，
取**最贴近 basis「左带内就近原位」**者 = **(31.55, 58.85)**（距原位 (31.05,56.0) **2.89 mm**）。

## 4. 落件前的**必办**一项（SPEC 对齐）

canonical SPEC `pd` 现仍声明 `C86.1 pad_pos [31.05,56.0] via_pos [30.275,56.0]`、`C86.2 [31.95,56.0]/[32.725,56.0]`
（与**修复前**的板 (32.4,36.0) 也不一致）。本次落点变更后必须**同步 bump SPEC**（rev-47）里的 `pd.decoupling` /
`pad_pos` / `via_pos`，否则「全局 PCB↔SPEC 1:1」pre-commit 会失败。
`k2_p4_w7_land_v1.py` 目前只追加 `_spec_rev_*` 变更记录、不改 `pd` 叶 ⇒ **落件前需扩展该落件器（或人工出 rev-47）**。

## 5. 本增量内发现并修正的工具缺陷（自曝）

初版 `k2_p4_c86_relocate_v1.py` 的候选文件名清洗 `…replace(".","p")` **误伤 `.kicad_pcb` 扩展名**，
导致结果板的同名配对 `.kicad_pro` 实际是**板的副本** ⇒ KiCad 取默认设计规则 ⇒ DRC 报 1005 error（真值应为 0）。
现改为只清洗 tag 段；修后复算 error 0（§3）。**教训（T-40）**：结果件命名清洗不得作用于扩展名；
落件前必须核「结果板同名配对 pro 是 pro、不是板的副本」。
