## 0. 结论先行（三句话）

1. **这块板不能装、不能供电、没有地平面。** 5 个插件连接器（含 12V 电源输入 J12）在板上**一个焊盘都没有**，全板钻孔数为 0；8 层里 3 个 GND 面 + 1 个电源面**全部未填充**，交付的 8 个铜层 Gerber 里**一共 0 个填充区**（G36=0）。
2. **它之所以"PASS"，是三件事叠出来的**：生成器的自检在空集合上真空通过、判据被成批关掉（9 条 DRC 规则 ignore）、结论在最后一层被重写（CO-47 把 25 个网划为"范围外"、HDI 通道把机器 FAIL 改判 ACCEPT）。**没有任何一道门问过"这块板装上元件能不能工作"。**
3. **器件布局的空白不是懒**，是"方案定了、施工图没落地"：走廊区确实按 L2 冻结留了空白，但没有任何一层把 46mm 板框、固定孔、回避区、走廊净跨写成图并机判。

### ① 方案投标（L1/L2 竞标）

- **该有**：候选 ≥2、统一裁判标准、**结构可行性预检硬门禁**（走廊闭合 + 焊盘墙穿透 + pin 逃逸可达）、冻结物与淘汰记录。
- **实际有**：`_shared/eda_core/l1_bid`、`L2/` 下的 `candidates/`、`evaluation/`、`L2_STRUCTURE_v1.0.md`、`L2_STRUCTURE_v2.0.md`、`stackup_8layer_decision.md`。`pm_gate/project.yaml` 甚至声明了 `l1_candidate_fields` 与 `l1_g15` 报告契约。
- **接线**：**断的**。`pm_gate/project.yaml` 的 `board_path: k2_v4.kicad_pcb` 指向不存在的文件（`[E13]`）→ 该配置根本载入不了，声明形同虚设。
- **会不会被关**：会——配置本身就是坏的。
- **漏掉**：
  1. **6L→8L 改判后没有重开 L2 竞标**。`stackup_8layer_decision.md`（08-19，"用户裁决定案 8 层"）是一份**数据对比报告**，不是 L2 竞标产物；`L2_STRUCTURE_v2.0.md` 仍写"6L 终定、8L 仅作回退候选"。→ 叠层决策与冻结物打架（N-02）。
  2. **冻结物与板实测从未对账**：L2 冻结"西走廊净跨 17.30mm（65.05→82.35）"，板上实测焊盘净距 **17.55mm**；"东 27.40mm（105.25→132.65）"，实测 **27.81mm**。两套口径（器件体宽 vs 焊盘外接框）从未对齐。
- **归类**：`输入数据缺陷`（8L 决策未回写 L2/SPEC）+ `监理流程缺陷`（无"冻结物↔板实测"对账机判）。

## 三、"为何 PASS"的机制定位（owner 直问）

**三台机制串联，把一块不可用的板洗成 PASS。**

### 机制① 生成器自检在空集合上"真空通过"（真值真空）

| 自检 | 代码位置 | 为何真空通过 |
|---|---|---|
| S1 焊盘重叠 | `tools/k2_gen_v5.py:553-568` | 遍历 `d["pads"]` 做两两比较。排针 `d["pads"] = {}` → 循环 0 次 → **PASS** |
| S5 坐标范围 | `tools/k2_gen_v5.py:606-617` | 只取 `x, y, _ = d["at"]`（**器件原点**），不看焊盘外扩 → 原点在框内就 PASS |
| S8 排针坐标冻结 | `tools/k2_gen_v5.py:702-711` | 只比对 `x/y` 两个数，不看旋转、不看焊盘是否存在 → **PASS** |
| pad 几何来源 | `tools/k2_gen_v5.py:332` | `d["pads"] = anchor["pads"]`——锚板自己就是 0 焊盘，缺陷被"已验证"继承 |
| 无 pad 数对账 | 不存在 | 从无任何检查比较"pad 数 vs 库/符号/网表引脚数" |

**结果**：生成器打印 `8/8 PASS`、打印 pads 总数，但没有任何一行把"排针应该有焊盘"变成断言。
`SPEC.components.pin_headers.pad_diameter: 1.5` **写下了却零引用**——这是"输入被写、执行器不读、判据不管"的完整断链。

### 机制② 判据被成批关闭

- `k2/hw/k2_v4_8L.l4.kicad_pro` 的 `rule_severities`：**9 条规则 = `ignore`**，其中包含 `via_dangling`（"过孔悬空或只连到一层"）、`silk_over_copper`、`silk_overlap`（`[E4]`）。
- **把 9 条打开后独立复跑 DRC：42 → 131 条**，新增 `via_dangling` 17、`missing_courtyard` 41、`silk_over_copper` 22、`silk_overlap` 9（`[E12]`）。
- 4 个 `ESC_*` keepout 的 5 个开关**全部 `allowed`** → "逃逸过渡区"在几何上是**空操作**（`[E6]`）。
- 所以"42 条全是 warning、0 error"是**配置产物**，不是设计质量。

### 机制③ 结论在最后一层被重写

1. **连通性**：`m13_v57_l5_dfm_dft_record.json` 的规则原文——`CO-47：在册（L4 施工）网必须 0 未连项；范围外网不计`。实测 `nets: 93`，`in_scope_nets: 68` → **25 个网（GND / P3V3 / P3V3_AUX / MCU_VDD / NO_CONNECT + 全部边带信号）被判为"范围外"**，178 个未连接项一次性移出判据，`in_scope_unconnected_items: 0` → **verdict PASS**（`[E18]`）。
2. **可制造性**：机器闸 `m13_v57_co146_jlc_dfm_gate.json` 的 `verdict` 字面是 **`"FAIL"`**（2 项：阻焊桥 / 过孔类型）。HDI 通道记录 `m13_v57_co146_jlc_dfm_hdi.json` 把前者改判为 `ACCEPT_L2_WITH_FAB_REVIEW`，`verdict: PASS_HDI`；交付 `README.md` 只写 **"16 PASS + 1 ACCEPT + 0 FAIL"**（`[E19]`）。
   > 注：走 HDI 通道本身是**有裁定支撑**的（L2 裁定 + 板厂评审）。问题在于——**同一个交付包里 `06_rulings/m13_v57_co146_jlc_dfm_gate.json` 的 `verdict` 仍然写着 `"FAIL"`**，板厂打开包会直接看到 FAIL。交付口径与包内证据不一致。
3. **从未运行的两道对比**：KiCad 自带的 `--schematic-parity`（板↔图）和共享层已建好的 `netlist_parity`（PCB↔SCH）——**一次都没跑**（N-03、N-04）。

### 一句话回答"为什么这样的板可以 PASS"

> **因为这条链上的每一道门问的都是"文件是否合规"，没有一道门问"板子是否可用"。**
> 焊盘数不进判据 → 0 个焊盘不影响 S1..S8；
> 铺铜填充不进判据 → 无平面不影响出 Gerber；
> 钻孔数不进判据 → 0 个孔不影响 DFM（DFM 只查"最小孔径"等上限，不查"是否有孔"）；
> 未连接项在册范围可裁 → 178 条用一个 CO-47 移出；
> 判据的开关可以改 → 9 条直接关掉；
> 结论可以重写 → 机器 FAIL 用通道记录改判。
> 三件事各自都"有理由"，合起来就是 **PASS 一个不可用的板**。

**责任环节定位**：环节⑤（施工至可打样）是"洗白"发生地；环节④（施工图纸）是缺陷发源地；环节①（投标）是 8L 决策与研究物脱节的发源地。

### 4.2 "布局没做"还是"方案没定"？

**答：方案定了，但施工图没落地——主体是"方案已定、布局未落地"，并且"布局落地的层级本身缺失"。**

三条依据：

1. **空白是"留给走廊的"，不是浪费。**
   U1→J3 空 15.00mm、J4→U6 空 17.55mm，正对应 L2 冻结的西走廊净跨 17.30mm / 东走廊 27.40mm。空白区就是走廊区，这是**方案要求**，不是布局偷懒。

2. **但器件坐标与走廊口径从未对账（两套口径差 0.25/0.41mm）。**
   L2 算的是"器件体宽"，板实测是"焊盘外接框"。差 0.25mm（西）与 0.41mm（东）在走廊利用率 51%–65% 的余量下不致命，但**这说明"冻结值 ↔ 板实测"这一环从来没有机判**——同样的机制下一次会长到致命。

3. **真正的空白是"底部 9.15mm"，根源是板框决策没落到几何层。**
   46mm 板框是 L1 决策，生成器却仍用 38mm 设计框，两者从未闭合。**没有任何一层**产出过"46mm 板框下：器件在哪、固定孔在哪、哪些区域不准放东西"的施工图。所以底部空、固定孔 0、回避区空——这三件事是同一个空洞的三个投影。

### 5.2 先修什么、为什么是这个顺序

**顺序：判据 → 现状清单 → 修板 → 判据全绿才出 Gerber。**

理由（这是本次事故的直接教训）：**10 条出厂维度里 7 条没有机判**。在没有判据的情况下重做板，只会再产出一块"PASS 但不可用"的板。所以：

1. **第 1 步（当天）：实现 J-1..J-10 的机判**（只读脚本 + 阈值，见 5.4）。不碰板。
2. **第 2 步：用判据跑现状**，产出一份自动生成的缺陷清单（会自动冒出 F-1..F-10 的完整列表，不需要人肉找）。
3. **第 3 步：按清单修板**（走副本，不动冻结 sha），每修一项跑一次判据。
4. **第 4 步：判据全绿才允许出 Gerber**，并在交付包里同时放"机器 verdict"和"重判 verdict"，二者不一致时**以机器 verdict 为准**。

### 10.1 L2-1 板框（机械）—— 以 46mm 为准，且已查明"两套框并存"

- **裁定**：canonical 板框 = `x[23,143] × y[33,79]`（120 × 46 mm）。生成器设计框必须同步改为 `y[33,79]`；`check_board_bounds` 与板框判据必须用同一框。
- **新证据（初稿未发现）**：走线**已经在用完整 46mm 框**——`y>71`（38mm 框外）的走线段 **292 / 2512 = 11.6%**，全部落在 `PCIE_*` 网，层分布 `In5.Cu 270 + In2.Cu 22`，最远到 **y=78.569**；另有 22 个过孔在 y>71；**器件 0 件在 y>71**。
- **结论修正**：U-08"下边大量空白"**不是浪费**——那 8mm 是**布线通道**（292 段 PCIe 走线在上）。真正的缺陷是"**器件按 38mm 排、走线按 46mm 走**"，同一流程里两套设计框并存且从未对账。
- **归类**：`输入数据缺陷`（设计框未随 L1 的 46mm 决策回写）+ `监理流程缺陷`（无"板框一致性"机判）。

### 10.2 L2-2 固定孔（机械）—— 已解出 4 孔位置

- **裁定**：**4 × M3 通孔（Ø3.2 NPTH，回避区 Ø6.0）**，位置由几何求解得出（孔全在板内、距板边 ≥1.5mm 材料、Ø6.0 回避区与**全层** pad/track/via 无干涉）：

|---|---|---|---|
| H1 | (26.10, 75.60) | 3.10 | 3.40 |
| H3 | (26.10, 36.10) | 3.10 | 42.90 |
| H2 | (139.60, 39.60) | 116.60 | 39.40 |
| H4 | (114.60, 36.10) | 91.60 | 42.90 |

- **可行域**：满足上述约束的孔位点共 **2952 个**（0.5mm 栅格），说明布局本身留有余量。
- **必须接受的副作用（诚实披露）**：**右下角不可放孔**——该区被 In5 的 PCIe 走线占用（见板面占用图，y≥74.5 且 x≥86 全被占）。因此 4 孔在右侧**不对称**。这是"46mm 框 + 布线占用底部右段"的必然结果；若要求严格对称，须先把该段走线改道（属 L3 施工，代价另计）。

### 10.3 L2-3 排针列（几何可行性）—— 保朝向，移列 + 移 2 枚无源

- **裁定**：**保留 `rot=90`**（"左边缘服务接口列"这一接口朝向属 L1 且已冻结，不改），**`column_x` 由 26.5 → 27.94mm**（22×1.27 栅格），并**移位 C73、C86** 两枚小无源（仍在左带内，不改变器件分区）。

| column_x | 结果 |
|---|---|
