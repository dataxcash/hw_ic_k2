## ③ 判据体系落地（含**功能级**判据）+ 权限隔离

### 3.1 两类判据必须分开，且不能互相冒充

| 类别 | 回答的问题 | 能证明什么 | 不能证明什么 |
|---|---|---|---|
| **J 类（文件/几何/工艺）** | 文件是否合规 | **排除已知低级错误、避免浪费一次打样** | **不能证明可用** |
| **V 类（功能级）** | **板子能不能用** | V1–V3 可机判；V4–V6 实测 | 仍需实测背书 |

> 明确立场（延续 K2-03 §1.5）：**J 类的定位是"别浪费一次打样"，不是"合格线"。** 拿 J 类当合格线，就是本次事故的成因。

### 3.2 J 类：由监理出具，ENG 只提供测量

- **我此前起草的 J-1..J-10 阈值全部作废**（K2-03 §八）—— 从"登记册现值列"反推的判据被现状污染。
- ENG 侧交付物只有：**测量实现 + 原始数据（schema 内无 `verdict` 字段）**。
- 每条判据的「应然值」写入 `criteria/manifest.yaml`，**由监理持有**。

### 3.3 V 类（功能级）：必须回答"能不能用"

| ID | 判据 | 可机判？ | 实现形态 | 为什么它能回答"可用" |
|---|---|---|---|---|
| **V1** | 网表闭合：每条声明网在板上**有实现**且补铜后**全量** unconnected = 0（**范围 = 权威网表全集，禁裁剪**） | ✅ 可机判 | 判定器：网表 × 板 pad/net 集合运算 + DRC | 直接杀死"整条网 0 焊盘"（今天 10 条网隐形） |
| **V2** | 引脚映射：每 (ref,pin) 有焊盘；每器件 pad 数 == 符号引脚数 | ✅ 可机判 | 判定器 | 杀死"缺 25 个 pad 的 MCU"类失效 |
| **V3** | 参考连续性：每段高速走线，相邻两层存在**连续**参考平面（投影覆盖该段全长） | ✅ 可机判 | 几何：段投影 ∩ 平面多边形 | 杀死"8 层板无平面"（今天 8 层 Gerber G36 全 0） |
| **V4** | 阻抗券实测 85Ω ±10% | 外部实测 | 板厂报告 | 材料/工艺真实达成 |
| **V5** | 各电源网到负载点直流压降 ≤ 预算 | 实测 | 首件实测 | 供电真实可达 |
| **V6** | **上电 → 各轨电压正常 → SWD 识别 MCU → I2C 扫到 FRU → 双路 x4 Gen4 链路训练成功 → 30min 无 AER** | **二值** | 首件 bring-up | **硬件事实，任何文件都伪造不了** |

**V1/V2/V3 的关键设计**：它们**以权威网表为 scope**，不引入"在册网/范围外网"概念 —— 从结构上消灭 CO-47 式裁剪（今天：93 网里 25 个被划出，178 条未连接一次性移出判据）。

### 3.4 权限隔离方案（按裁定 §三，逐条对应）

| 裁定条文 | 落地形态 | 强制手段 |
|---|---|---|
| §三-1 判据放只读位 | `criteria/manifest.yaml` 属主 = 监理账号/CI，权限 `0555`；`adjudicate.py` **源码**可由 ENG 起草，但**运行副本**置于 ENG 写域之外（D-1） | **ENG 身份下 `test -w criteria/manifest.yaml` 必须失败**；`test -w <判定器运行副本>` 同样失败 |
| §三-2 变更走裁定留痕 | `criteria/CHANGELOG`（前后值+理由+日期+裁定人）；判定器校验 manifest sha 与账本锚 | sha 不一致 → FAIL |
| §三-3 verdict 不可被重判 | 测量产物 schema **无 `verdict` 字段**；verdict 由判定器派生；交付包内唯一 verdict | 有 `verdict` 字段即 schema 非法 → FAIL |
| §三-4 禁判据自废 | **deny-by-default**：有效规则集 ≠ manifest 应然集 → FAIL；`ignore` 无台账 → FAIL | 与 `.kicad_pro` 解耦（判定器在副本上覆盖后跑） |

**为什么这是"权限级"而不是"自觉"**：
1. **判据不在被审对象里** —— DRC 的生效 severity 来自外部 manifest（副本覆盖），**改 `.kicad_pro` 无效**。可行性已实测：副本上把 9 条 ignore 改回 → DRC 42 → **131** 条。
2. **产物没有可写的结论字段** —— "重写结论"无落点。
3. **缺件 = FAIL** —— 今天"无 `pipeline.yaml`"静默通过（实测 `check_all_projects_coverage()` 返回 `(True, '全部 1 项目…完整')`），改后为硬 FAIL。

### 3.5 判据的质量门（**判据自己也要被验收**）

- **负控**：判据必须能抓住本板全部已知缺陷（P1 判据 1）。
- **正控**：伪造的绿必须被判据拒绝（P1 判据 2）。
- **规则**：**未通过正/负控的判据，不得用于任何验收。**

## ④ 真源归零计划

### 4.1 为什么必须先归零（判定：**归零前的"绿"不算绿**）

对一张未经归零的图求一致，得到的是"板 vs 这张图"的关系，与"板正确"**没有因果**。J-6 现在拿板去对一张**可能本身是错的**图，结论无意义。

### 4.2 归零四步

| 步 | 动作 | 责任 | 判据 |

| **Z1** | **天真源声明**（见 §⑧ L2-10）：以「L1 拓扑冻结 + 器件 datasheet + vendor 球映射资产」为真源；原理图/网表/板三者由它派生（板不得手改） | **ENG/监理**（记账/流程，非 L1）；**仅当器件集合需变时**才升级 owner | 真源声明落档 + 三方一致 |

## ⑧ 本轮 L2 自裁补充（按第二章，L2 由 ARCHER 自裁，不等 owner）

### L2-9 热机械（U6 / DS320PR1601）—— 独立复算 + 裁定

**事实（我独立复算，口径 = 器件手册 θJA(high-K)；来源 `L2_RULING_u6_thermal_v1.md` 引 TI SNLS683）**

| 档位 | P (W) | Tj = 40 + 17.4·P | 判定 |
|---|---|---|---|
| EQ0-2 typ | 4.7 | **121.8 °C** | 超限（> Tj,max 120） |
| EQ0-2 max | 6.0 | 144.4 °C | 超限 |
| EQ5-19 typ | 5.8 | 140.9 °C | 超限 |
| EQ5-19 max | 7.0 | **161.8 °C** | 超限 |

- 最轻档允许环境温度：`Ta_max = 120 − 17.4×4.7 = 38.2 °C`（**< 40 ⇒ 自然对流下全部档位不可行**）
- 达标所需等效热阻：最轻档 `≤ 17.02 °C/W`（手册 17.4，**仅需改善 2.2%**）；最重档 `≤ 11.43 °C/W`（**需改善 34%**）

**板内实测（我独立复算）**：U6 共 354 球，其中 **GND 球 152**、**无网 108**；U6 域（外扩 2mm）内 GND via = **68**（既有裁定按另一口径计 66，差 2 属口径差）；GND 平面 = In1/In3/In6（但**三面全未填充**，见 F-2/N-01）。

**L2 裁定（我职权内的部分）**

| 编号 | 裁定 | 依据 |
|---|---|---|
| **L2-9a** | U6 域 **GND via 阵列补强**为既定义务（当前 68，按 152 个 GND 球比例显著不足） | PCB 热阻 = L2 |
| **L2-9b** | In1/In3/In6 三面在 U6 域的**覆盖最大化**（前提是先满足 L2-5 的"填充前置"） | 同上 |
| **L2-9c** | U6 域 F/B 侧**铜面最大化** | 同上 |
| **L2-9d** | **量化边界（本裁定的核心结论）**：PCB 侧措施**只能覆盖最轻档**（缺口 2.2%）；**EQ5-19（现实长通道典型档）需 ≤ 11.43–13.79 °C/W，PCB 侧不可达**——纯 PCB 手段无解 | 上表算术 |

> **L2-9d 是 L2 判定的终点**：它回答的是"PCB 能提供多少热阻"。**超过这一点就不是 L2 能答的了**（见 §⑨）。
