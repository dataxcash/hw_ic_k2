**「BLOCK 优于 #K2-367 v1」——同意，三条硬理由（非客套）**：
1. **可判定性更高**：v1 的"损伤集"由 pad 局部推出，**抓不到"未穿越但被移动铜侵犯"的邻居**（本件实测反例 `LED_A`）；BLOCK 以**区域**为第一性对象，能把"块外是否真不动"变成一条**逐段 diff = 0** 的可判定判据。

## 1 「穿边即重连」判据是否充分？bridge 并入 N\* 是否正确？

**判定：方向认可；谓词与对象两处须修正。**

### 1.1 修正一：谓词须**膨胀**（否则边界外侧漏网）

「与 ∂R 相交」只覆盖**真的穿越**的线；但**紧贴边界外侧、未穿越**的平行线，会被**移动后的块内新铜**侵犯。正确谓词：

```
N* = { 网 : pad ∈ R }  ∪  { 网 : 铜 ∩ ( swept ⊕ clearance ) ≠ ∅ }
      swept = R ∪ (R + Δ)
```

**k2 实测（逐 guard 复算）**：

| 谓词 guard | 判入 N\* 的网数 | 超出「pad∈R」的网 |
|---|---|---|
| 0.000 mm（纯穿越） | 21 | **0** |
| **0.175 mm（＝本板 DRC 间隙）** | 21 | **0** |
| **0.500 mm** | **22** | **+1 ＝ `LED_A`** |
| 1.000 mm | 22 | +1 ＝ `LED_A` |

⇒ 本实例在**恰好等于 DRC 间隙**时侥幸不漏；**规则本身必须是膨胀式**（`LED_A` 的铜落在扫过区 0.5mm 内、且在 R 内**无 pad**，旧谓词与"pad 归属"型谓词**双双抓不到它**）。**这一条直接反驳 #K2-367 v1 的"pad 局部损伤集"**。

### 1.2 修正二：重连的**对象是"穿边端口"，不是"整条网"**

BLOCK 的收益必须落成"只拆/只连 ∂R 上的端口"，否则退化成现状。**k2 实测（左区域 21 网）**：块内段 **496** · **穿边段 23** · 块外段 **559**；孔：块内 **86** · 块外 **369**。⇒ 重连对象 = **23 个穿边端口**（vs 现 M2 拆 1078 段）。

### 1.3 bridge 并入 N\* ——**正确，但在 k2/l14 本场景为空集**

- 「进出均在块外、铜却穿过扫过区」的桥：**实测 0 条**（扫过区 = `[24.13, 34.00, 49.45, 65.41]`，与块外网铜无交）。
- 结论：该条款**保留为预防项**（换框/换板即可能非空），**不是可删项**；本窗它不产生工作量。

## 2 外部端口固定：块外一侧是否"确实零合法性变化"？

**判定：几何层认可；"零合法性变化"这句须反驳并按膨胀条件改写。**

- **几何层成立**：块外铜**不动** ⇒ 对块外网而言，其端子是世界坐标固定的**固定端口**（这是 BLOCK 的强项，也是找路域能被框死在块内的原因）。
- **合法性层不成立（实测反例）**：块外铜几何不变，但**块外铜与"移动后的块铜"的间距关系会变**。`LED_A`（块外网、R 内无 pad）的铜落在扫过区 **0.5mm** 内 ⇒ 其间隙关系**确实改变**。
- **正确表述**：

> 块外合法性不变 ⟺ **R 被 (clearance + guard) 膨胀**（把交互晕圈并入 R），此时"块外"才含"与移动铜间距 ≥ clearance"的可证条件。

  ⇒ 建议 BLOCK 定义中的 R 一律理解为 **R_expanded = R ⊕ (clearance + guard)**；实测在 0.175mm 下额外网数 = 0（本场景无溢出），但该条件是**规则**、不是巧合。

- **顺手揭一处现况冲突**：当前 M2 拆的是**整网的全部铜**，包括块外 **559 段 / 369 孔** ⇒ **与"块外不动"直接冲突**。BLOCK 落地的**第一条改动**就是把 M2 的拆除域从"整网"改为"R 内段 + 穿边段"。

## 3 分层 ＋ 过孔"棱柱"语义 ↔ `eda_eng` / `board_model` 对接

**判定：认可，且已有现成落点；具名两处差距。**

### 3.1 现成落点（`_shared/eda_core/board_model`）

| BLOCK 概念 | 现成设施 |
|---|---|
| 区域 R / swept | `geometry.BBox`（`inflate / overlaps / contains`）· `board.BBox.inflated/overlaps` |
| 三分法分类 | `BBox.contains` 端点判定 ＋ `SpatialIndex.query_bbox / query_segment`（先粗筛候选再精判，避免全板扫描） |
| 逐层障碍 | `adapter.BoardAdapter` ＋ `Track.bbox`；`RuleEngine.get_clearance` 提供间隙 |
| 块体搬运 | `board.Component.move_to`（不变式：**任何移动必须经 move_to，联动更新 pads 与下游索引**） |

⇒ 建议在**共享层**新增通用对象 **`Block{bbox, swept, refs, class_map}`**（**零单板特判**，承容器级 AGENTS.md 共享层约束），`eda_eng` 经 `RouteInput` 消费。

### 3.2 差距一：`eda_eng` 目前**未接 board_model**

现状是直接用 `pcbnew`；BLOCK 落地需一层 `RouteInput` 适配（不新增单板逻辑）。

### 3.3 差距二：**过孔棱柱未做全 —— 换层只核"两端层"，未核 span 内每一层**（具名缺陷）

- `obstacles_from_board()` **已把 via 记在其跨越层的每一层**（棱柱的"面"对齐），`grid_of(for_via=True)` 也给了**via 站点净空**网格 —— 数据结构侧**是**棱柱友好的。
- **但** `maze_route()` 换层时只查 `gv[L]` 与 `gv[L2]`：

```python
if gv[L]["blocked"][i*...] or gv[L2]["blocked"][i*...]: continue   # 只查两端层
```

⇒ **跨 >2 层的 via（如 F.Cu↔In4.Cu 途经 In1/In2/In3）未逐层校验**，违反"过孔＝棱柱、动它须穿透各层皆合法"。
**修法**（并入 §6 计划）：换层时对 **span 内每一层**做 via 站点净空检查，并对 via 的**全体跨越层**取联合净空。

### 3.4 分层语义

`obstacles_from_board(board, ignore_nets, layer)` 本就**逐层**取障碍（层不匹配即跳过）⇒ "逐层各修各的"已在；缺的是**同一 via 的多层联合合法性**与**同一条 R 在各层的重复使用**（R 应一次性定义、逐层复用）。

## 4 敷铜「拆掉重铺」↔ 既有 refill 流程

**判定：意图认可，但"拆 zone 多边形"在本板是错的；且先修一处自曝缺陷。**

### 4.1 本板铺铜的实相（实测 zone 清册）

| zone | 网 | 层 | bbox | 与 R 相交 |
|---|---|---|---|---|
| 8 / 9 / 17 | **GND** | In1 / In3 / In6 | **`[23.3, 33.3, 142.7, 78.7]`（整板）** | **是** |
| 13 | MCU_VDD | In4 | `[23.3, 33.3, 57.75, 78.7]` | **是** |
| 15 / 12 | P3V3 | In4 | `[34.27,34.02,58.42,40.25]` / `[57.95,…,142.7,78.7]` | **是 / 否** |
| 10 / 11 | P3V3_AUX | In4 | `[27.95,35.98,52.75,54.27]` / `[52.2,52.02,59.15,62.52]` | **是 / 否** |
| 14 / 16 | 12V_IN | In4 | `[25.02,36.84,35.98,41.75]` / `[24.6,34.9,29.4,41.2]` | **是 / 是** |
| 4 | （无名 · rule/keepout） | F/B/In1 | `[22.07,32.07,28.07,38.07]` | **是** |

⇒ 铺铜**不是块内小铜皮**，而是**整板大 zone**。故"拆掉重铺"在实现上只能是 **重跑 zone filler**（填充全局重算，仅变动邻域不同），**不是删 zone 多边形**。

### 4.2 自曝缺陷：`relocate` 的第 5 步「复敷铜」**当前是空操作**

- `relocate_chain()` 第 5 步走 `route --apply-batch` → **`apply_routes()`**；该函数**没有** `ZONE_FILLER` 调用（只有单网的 **`apply_route()`** 调了）。
- ⇒ #K2-366 §二 第 5 步 **未实现**；attempt 3 的 `isolated_copper 8` 与 C2 假升，**部分来源即此**（承 #K2-362 §二.1 对铺铜态的首要嫌疑）。
- **修法**：批路径落板后统一 `ZONE_FILLER(board.Zones())`，并把 **`zones_refilled`** 写进收执（fail-closed：refill 失败即具名 FAIL）。

## 5 HS 冻结区互斥：16 条 PCIe 扇出能否全在块外？（含边界建议坐标）

**判定：认可（可行），且余量很大。**

**实测包络**：

| 对象 | 铜包络（mm） |
|---|---|
| **16 条 PCIe 扇出**（`PCIE_DN0..7_P/N` · J2→U6） | **`[84.58, 53.88, 142.56, 78.74]`**（x_min **84.58**） |
| 全部 `PCIE_*` 网铜 | `[53.02, 33.27, 142.56, 78.74]`（x_min **53.02**） |
| 左区域扫过区 | `[24.13, 34.00, 49.45, 65.41]`（x_max **49.45**） |

**建议边界**：

```
R_block = [22.95, 32.95, 51.50, 66.50]          # 左/上取板框（Edge.Cuts y_min = 32.95）
```

| 校核 | 读数 |
|---|---|
| 含扫过区 | x 余量 **2.05mm** · y 余量 **1.09mm** ✓ |
| 距最近 `PCIE_*` 铜（53.02） | **1.52mm**（硬上界 = 53.02 − 0.175 = **52.85**） ✓ |
| 距 16 条 DN 铜（84.58） | **33.1mm** ✓ |
| 结论 | **16 条 HS 扇出完全在块外 ⇒ 逐段不动** ✓ |

（若 M3 首跑证 R 内可容不下 23 条接驳，x_max 可在 `[49.45, 52.85]` 内调，**不得超 52.85**。）
