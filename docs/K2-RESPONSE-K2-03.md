**结论：J-2 这类"同名网络连通性"判据，对"整条网根本没被实现"这一失效模式永远沉默。** 这正是本板真实存在的病。

## 二、缺口 2：如何使"成批关闭判据""重写结论"**结构上不可能**

先认账：我把 `silk_*` / `via_dangling` 两条定死 = **打地鼠**；我写的"以机器 verdict 为准" = **自觉条款**。两条都不治机制。

### 2.1 三层切分（这正是裁定要求的"权限级"形态）

| 层 | 内容 | 谁写 | 谁读 |
|---|---|---|---|
| **判据资产** | manifest：每条规则的**应然** severity、阈值、**豁免清单**（含裁定号/理由/生效期） | **监理**（owner 批变更） | 判定器 |
| **测量资产** | 原始数据：DRC JSON、几何 JSON、实测日志。**schema 内禁止 `verdict` 字段** | **ENG** | 判定器 |
| **判定** | 判定器读 判据资产 + 测量资产 → 产出 verdict + 账本条目 | **监理** | 所有人 |

### 2.2 使机制②「成批关闭判据」不可能

三个动作，缺一不可：

1. **比较，而非信任**：判定器每次取 manifest 的"应然规则集"，与产物的**有效**规则集逐项比对。**任何 `ignore` 若不在 manifest 豁免清单里 → FAIL。**
2. **判据不放在被审对象里**：DRC **不使用板内 `.kicad_pro` 的 severity**。判定器在**副本**上以 manifest 的规范值覆盖后再跑。
   - *可行性已实测*：我在 `/tmp` 副本上把 K2 那 9 条 ignore 改回后重跑，DRC 由 42 → **131 条**（`via_dangling 17`、`missing_courtyard 41`、`silk_over_copper 22`、`silk_overlap 9`）。说明"外部指定规则集"这条路技术上走得通。
   - 效果：**改 `.kicad_pro` 变得无效**（生效值来自外部）；要真放宽必须进 manifest，而 manifest 不在 ENG 可写域。
3. **fail-closed**：manifest 缺失/不可读/**未接线**/不可解析 → **一律 FAIL**。
   - 今天的行为是 fail-open，实测见 §四。

### 2.3 使机制③「重写结论」不可能

1. **产物 schema 删除 `verdict` 字段**：机器只产出**测量**，verdict 由判定器**派生**。
   - 今天：`m13_v57_co146_jlc_dfm_hdi.json` 能写 `verdict: PASS_HDI` 并把机器 FAIL 改判 → 交付 README 只写"0 FAIL"。
   - 改后：**没有可写的字段**，改判无处安放。
2. **交付包里只允许一种 verdict**（判定器产出）；人工/通道说明只能进**不参与判定**的独立字段。
3. **裁剪必须付代价**：scope 恒 = 权威网表全集；任何豁免逐条列名 + 裁定留痕，并**自动出现在交付封面**（不静默改数）。

### 2.4 诚实边界（必须写明，否则就是新的自觉条款）

上述 2.2 / 2.3 **全部依赖一个前提：ENG 不能写 manifest 与账本**。
**在本机同 UID 下，这一点做不到** —— 所有文件同属一个账号，权限位可被自己改回。

因此：
- **可落地的最强形式** = **判据与判定权交给不同的写入主体**（独立 OS 账号 或 CI runner 持有 manifest/判定器/账本）。**这需要 owner 批准资源。**
- **若不批准**：本方案退化为自觉条款。**我不会把它包装成"机制"。**

## 三、缺口 3：真源如何归零？归零前的"绿"算不算绿？

### 3.1 判定：**不算绿。**

对一张未经归零的图求一致，得到的是"板 vs 这张图"的关系，与"板正确"**没有因果**。判据必须先声明"以何为真"——而"器件集合/球映射"属 **L1**，只能 owner 裁定。

### 3.2 我做的三源对账实测（归零的起点，也让"归零前"有了数）

| 对账项 | 实测 |
|---|---|
| 网表节点逐引脚 vs 板 | 合计 **489**：**一致 424** / **不一致 15** / **网表要求但板上无焊盘或无器件 50**（一致率 **86.7%**） |
| 15 条"不一致"的构成 | **全部是 U6**：板上焊盘存在但 **无网**（8 条 strap + MODE + I2C2 SCL/SDA + 4 个电源/地球） |
| 板上焊盘未被网表覆盖 | **177 / 616 = 28.7%** |
| 网名集合 | 板 92 / 网表 101 / 交集 91；**板上有、网表无 = `NO_CONNECT`**（自造网） |
| 网表有、板上 0 焊盘的网 | **10 条**（见 §1.3） |
| 生成器可解析性 | **实测 TypeError**：`k2_gen_v5.py` 期望 `pins = {pin_name: [pad]}`，当前 YAML 是 `{side: [[名, 号, 向, 类]]}` ⇒ **真源与执行器不同构** |

> 即：真源不只是"陈旧"，而是**三源互不相等 + 与执行器 schema 都不兼容**。

### 3.3 归零程序（提案；第 1 步需 owner 一句话）

1. **owner 裁定"以何为真"**：以「**实际要装的 BOM + 器件 datasheet**」为唯一真源；原理图 / 网表 / 板 **三者都必须由它派生**（板不得手改）。*这一步是 L1（器件集合/球映射），只能 owner 定。*
2. **三源同构化**：refdes 集合相等 → 每个 refdes 的「符号引脚集 == 封装焊盘集 == 板上焊盘集」→ 逐引脚网成员相等。
3. **归零完成判据（可机判）**：上述三项差异**全 0**，且生成器**可复跑**（输入文件齐 + 两次输出 sha 相同）。
4. **归零前的一切"绿"，标记为 `unbaselined`，不得作为合格证据。**

### 3.4 由此产生的判据修订要求（交给监理）

J-6 必须**先声明基准**（`baseline: <三源归零后的冻结 sha>`），判据文本改为"**板 == 已归零的基准**"；基准未归零时 J-6 输出 `unbaselined`（**按 fail-closed = 不合格**），禁止给出绿。

## 七、方案修订 v2（判据归属落地）

### 7.1 与裁定条文的逐条对应

| 裁定要求 | 本方案的落地形态 | 由谁实现 |
|---|---|---|
| §三-1 判据文件放只读位 | `criteria/manifest.yaml`（应然 severity + 阈值 + 豁免清单）置于 ENG 无写权限的目录；判定器在副本上以 manifest 覆盖后跑 DRC | 监理（内容）+ owner（权限位/账号） |
| §三-2 判据变更走裁定留痕 | manifest 每次变更写 `criteria/CHANGELOG`（前后值 + 理由 + 日期 + 裁定人）；判定器校验 manifest sha 与账本锚一致 | 监理 |
| §三-3 机器 verdict 不可被重判覆盖 | 产物 schema **无 verdict 字段**；verdict 由判定器派生；交付包内唯一 verdict | 监理（判定器）+ ENG（测量） |
| §三-4 禁判据自废 | **deny-by-default 比对**：有效规则集 ≠ manifest 应然集 → FAIL；`ignore` 无台账 → FAIL | 判定器 |

### 7.2 判据资产的 schema 草案（**空壳由我提，内容归监理**）

```yaml
# criteria/manifest.yaml  —— 监理持有；ENG 只读
manifest_version: 1
board: k2_v4_8L.l4
criteria_sha: <判定器自校验用>
rules:                      # 由监理填写"应然值"
  via_dangling: error
  silk_over_copper: error
  silk_overlap: error
  # ... 全部 62 条
exemptions:                 # 任何放宽必须在此逐条登记，否则 FAIL
  - rule: solder_mask_bridge
    ruling: <裁定号>
    reason: <理由>
    date: <日期>
    expires: <日期>          # 到期未复核 → FAIL
thresholds:                 # 由监理填写
  <criterion_id>: <value>
scope:
  connectivity: authoritative_netlist   # 禁止任何"范围外"裁剪
```

### 7.3 落地步骤与验收

| 步 | 动作 | 产物 | 验收 |
|---|---|---|---|
| S1 | 监理出具判据 manifest（含阈值） | `criteria/manifest.yaml` | 覆盖 K1/K2/后续板；无 "ignore 未登记" |
| S2 | owner 批权限位/账号（三件套之一） | 目录属主 + 只读位 或 CI runner | ENG 无法写 manifest/账本 |
| S3 | 判定器实现（监理） | `adjudicate.py` | 输入=manifest+测量；输出=verdict+账本 |
